# 마이페이지 설계 — 보관함과 설정

날짜: 2026-08-28. 1차(자료 보관)는 `2026-08-27-storage-and-mypage-design.md` 에 있고
이 문서는 그 §11 을 받아 2차를 정한다.

## 1. 무엇을 만드는가

로그인한 사람이 지난 자료를 다시 보고, 자기 설정을 고치는 화면 하나를 만든다.
1차에서 서버에 쌓기 시작한 것을 사람이 볼 수 있게 하는 것이 전부다.

## 2. 들어가는 곳

상단 막대의 닉네임을 링크로 바꾼다. 누르면 `/me` 로 간다.

상단 항목을 늘리지 않는다. 매일 쓰는 넷(홈·생활과 봉사·파수대 연구·연설)을 앞에
두고 가끔 쓰는 것을 뒤로 보낸다. 휴대폰에서 상단이 줄바꿈되지 않는다.

## 3. 보기는 새로 만들지 않는다

이 설계의 중심이다. 보관함에서 항목을 누르면 보관함 안에서 펼치지 않고 원래 그
화면으로 보낸다.

- 연구 답변 → `/watchtower?date=YYYY-MM-DD` 또는 `/life-ministry?date=...`
- 연설 자료 → `/talk?주간=YYYY-MM-DD&배정번호=N`

두 화면은 1차에서 이미 저장된 자료를 알아서 불러온다. 필요한 것은 두 화면이 URL
질의에서 주간을 받아 첫 선택으로 삼는 것뿐이다.

이렇게 하면 답변 카드, 성구 펼침, 원고 네 탭, 복사, 내려받기가 그대로 따라온다.
보관함 전용 뷰어를 만들면 그것들을 다시 만들거나 반쪽만 보이게 된다.

**주의** — `/watchtower` 는 저장된 것이 없으면 새로 만든다. 보관함 목록에 있다는 것은
저장되어 있다는 뜻이므로 보통은 만들지 않는다. 다만 저장 판(`현재판`)이 올라간 뒤에는
낡은 자료를 없는 것으로 보므로 다시 만든다. 이것이 맞는 동작이다.

## 4. 화면 구성

`/me` 한 화면에 두 판을 세로로 쌓는다. 탭을 두지 않는다.

1. **보관함** — 연구 답변 목록, 연설 자료 목록
2. **설정** — 화자 프로필 일곱

### 4.1 연구 답변 목록

저장된 주간 전부를 날짜 내림차순으로 보인다. 누가 만들었는지 기록하지 않으므로
"내가 만든 것" 을 가려낼 수 없다. 보이는 것과 실제가 같은 쪽을 골랐다.

한 줄에 주간 날짜와 종류(파수대 연구 / 생활과 봉사)를 보인다. 누르면 §3 대로 보낸다.
같은 주간에 둘 다 있으면 파수대 연구를 먼저 놓는다.

**지우기를 두지 않는다.** 이 자료는 회중이 나눠 쓴다. 한 사람이 지우면 그 주 답변이
모두에게서 사라지고 다음 사람이 호출 값을 다시 치른다. 답변이 마음에 안 들 때는 그
화면의 "다시 만들기" 가 이미 해결한다. 남는 것은 실수로 누를 위험뿐이다.

**내려받기도 두지 않는다.** 답변 전체를 마크다운으로 만드는 코드가 새로 필요한데
지금은 없다. 보기가 "언제든지 다시 볼 수 있게" 라는 목적을 채운다. 나중에 원하면
따로 붙인다.

### 4.2 연설 자료 목록

내 것만 보인다. 주간 내림차순, 같은 주에서는 배정 번호 순.

한 줄에 주간 날짜, 배정 제목, 만든 때를 보인다. 보기·지우기·내려받기를 둔다.

- **보기** — §3 대로 `/talk` 로 보낸다. 교재 페이지가 고쳐져 그 주 배정 순서가 바뀌었으면
  1차의 배정제목 대조가 막아 원고가 복원되지 않고 그 자리의 배정만 골라진 채로 열린다.
  틀린 원고를 맞는 것처럼 보이는 것보다 낫다
- **지우기** — 확인을 한 번 묻는다. `SavedNotice` 가 쓰는 AlertDialog 를 그대로 쓴다
- **내려받기** — 준비 원고 하나를 `.md` 로 받는다. 나머지 산출물은 보기로 들어가면 있다

### 4.3 설정

`SpeakerProfileForm` 과 `use설정` 을 그대로 얹는다. 연설 화면과 같은 훅이므로 한쪽에서
고치면 다른 쪽에 바로 반영된다.

## 5. 서버

### 5.1 `GET /api/my-archive`

응답:

```
{
  "연구답변": [{ "종류": "watchtower", "주간": "2026-08-24" }],
  "연설": [{ "주간": "2026-08-24", "배정번호": 3, "배정제목": "...", "만든때": "..." }]
}
```

- **연구답변** — `저장소.목록('weeks/')` 의 경로 이름만 파싱한다. 파일을 읽지 않는다.
  종류와 주간이 경로에 다 들어 있다
- **연설** — `저장소.목록('users/{회원번호}/talks/')` 를 훑고 각 파일을 읽는다. 배정
  제목과 만든 때가 파일 안에 있어서다

목록을 못 읽으면 빈 배열을 돌려준다. 보관함이 비어 보이는 것이 화면이 막히는 것보다
낫다. 개별 연설 파일 읽기가 실패하면 그 줄만 뺀다.

### 5.2 `DELETE /api/my-talk?주간=&배정번호=`

기존 파일에 방식 분기를 더한다. 새 파일을 만들지 않는다.

경로는 서버가 세션의 회원번호로 만든다. 남의 자료를 가리킬 방법이 없다.

없는 것을 지워도 성공으로 답한다. 두 번 눌렀을 때 오류를 보일 이유가 없다.

### 5.3 로컬 서버

`src/web-server.mjs` 에 같은 둘을 단다. 두 면이 어긋나면 로컬과 배포가 달라진다.
이것은 1차 검토에서 매번 걸렸던 자리다.

## 6. 새 모듈

`src/archive.mjs` — 저장소 경로 문자열을 목록 항목으로 바꾸는 순수 함수를 둔다.
저장소 없이 시험할 수 있다.

- `주간경로파싱(경로)` → `{ 종류, 주간 }` 또는 `null`
- `연설경로파싱(경로)` → `{ 주간, 배정번호 }` 또는 `null`

모양이 안 맞으면 던지지 않고 `null` 을 준다. 저장소에 예상 밖의 이름이 있어도 목록
전체가 죽지 않아야 한다.

`src/talk-store.mjs` 에 `연설지우기({ 저장소, 회원번호, 주간, 배정번호 })` 를 더한다.
경로 만들기는 try 밖에 둔다. 잘못된 입력을 저장소 문제로 덮으면 원인을 못 찾는다.

## 7. 화면 쪽 변경

- `web/src/App.tsx` — 닉네임을 `/me` 링크로, `/me` 라우트를 lazy 로 더한다
- `web/src/routes/MyPage.tsx` — 새 화면
- `web/src/routes/StudyPrep.tsx` — `?date=` 를 첫 선택으로 받는다
- `web/src/routes/Talk.tsx` — `?주간=`, `?배정번호=` 를 첫 선택으로 받는다
- `web/src/components/DraftOutput.tsx` — 안에 있는 내려받기 함수를 `lib/download.ts` 로
  옮겨 보관함과 나눠 쓴다
- `web/src/lib/archive-api.ts` — 목록 받기와 지우기 호출

## 8. 시험

- `src/archive.mjs` — 경로 파싱. 맞는 모양, 틀린 모양, 다른 사람 경로
- `src/talk-store.mjs` — 연설지우기가 맞는 경로를 지우는지, 잘못된 입력에 던지는지
- `web/src/smoke.tsx` — 마이페이지가 마운트되는지

브라우저 확장이 로컬에 붙지 못하므로 SSR 스모크가 유일한 마운트 확인이다. 실제 화면은
배포 뒤에 형제가 본다.

## 9. 알면서 남기는 것

**연설 목록이 파일을 하나씩 읽는다.** 개인 자료라 지금은 몇 개뿐이라 괜찮다. 몇 년
쌓이면 목록 여는 것이 느려진다. 원인은 1차에서 파일 이름에 배정 제목을 넣지 않은
것이다. 지금 이름을 바꾸면 이미 저장된 자료가 안 보인다. 천장을 주석으로 남기고
느려지면 고친다.

**`저장소.목록` 이 쪽 나누기를 하지 않는다.** Vercel Blob 의 기본 상한은 한 번에
1000개다. 회중 규모에서 주간 자료가 그만큼 쌓이려면 십 년 넘게 걸린다. 넘으면 뒤가
잘린 채 조용히 보인다. 문제가 될 때 고친다.

## 10. 하지 않는 것

- 보관함 안에서 자료를 펼쳐 보는 전용 뷰어
- 연구 답변의 지우기와 내려받기
- 검색이나 거르기. 목록이 짧다
- 쪽 나누기. §9 와 같은 이유다
