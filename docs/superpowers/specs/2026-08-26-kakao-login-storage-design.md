# 카카오 로그인과 결과물 서버 보관 설계

- 작성일은 2026-08-26이다.
- 이 문서는 웹앱에 계정과 저장소를 처음 들이는 설계다. 지금까지 이 앱에는 인증도
  데이터베이스도 없었다.
- 배포에 걸리는 미확인 위험이 하나 있다. 9절에 있다.

## 1. 무엇을 왜 만드는가

김동언 형제의 말을 그대로 옮기면 이렇다.

> 각자 로그인 하여 자신이 사용하여 얻은 결과물을 서버에 저장해두었다가 언제든지
> 다시 꺼내서 볼 수 있게 하려고 함이다. 화면을 나갔다가 돌아오면 자료가 유실되어
> 토큰이 너무 아깝다.

두 가지를 푼다.

1. **유실** — 화면을 벗어나면 만들어 둔 답변과 원고가 사라진다. 지금은 브라우저
   메모리에만 있다.
2. **낭비** — 같은 자료를 다시 만들려면 OpenAI 를 다시 부른다.

낭비 쪽에서 코드를 읽다가 발견한 사실이 설계를 크게 바꿨다. **생활과 봉사와
파수대 연구의 결과는 사용자와 무관하다.** `prepareLifeAndMinistry(날짜)` 와
`prepareWatchtower(날짜)` 는 날짜만 받는다. 프로필이 들어가지 않는다.

즉 회중 세 사람이 같은 주 파수대를 준비하면 지금은 OpenAI 를 세 번 부른다.
내용은 사실상 같다. 주간별로 한 번만 만들어 공유하면 호출이 사람 수만큼 줄고
두 번째 사람부터는 기다림도 사라진다.

연설은 다르다. `프로필`(성별·연령·임명·스타일·문체견본·분당글자수)이 들어가므로
사람마다 결과가 다르다. 개인 자료로 보관한다.

| 주간 자료 | 주간별 하나를 모두가 공유 | 사용자와 무관한 결과다. 토큰이 사람 수만큼 줄어든다 |
| 연설 자료 | 사용자별 보관 | 프로필이 들어가 사람마다 다르다 |
| 저장소 | Vercel Blob 비공개 저장소 | 접근 패턴이 키 조회와 접두사 목록뿐이다. 3절에 있다 |

## 3. 저장소 — Vercel Blob 비공개 저장소

### 왜 데이터베이스가 아닌가

이 앱이 저장소에 하는 일은 둘뿐이다.

- 아는 키로 하나 꺼낸다
- 접두사로 목록을 뽑는다

조인도 검색도 집계도 없다. Postgres 는 이 일에 과하다. 업체가 하나 늘고 드라이버와
스키마 관리가 붙는다. Redis 는 목록 뽑기가 `SCAN` 이라 어색하고 원래 캐시 성격이다.

Blob 은 비공개 모드를 지원한다(2026-07-15 문서 기준). 읽기에 인증이 필요하고
내용이 함수를 거쳐서만 나간다. URL 을 아는 누구나 읽는 예전 방식이 아니다.
Hobby 요금제에서 1GB 무료다.

**저장소를 만들 때 반드시 `Private` 로 만든다. 만든 뒤에는 바꿀 수 없다.**
Public 으로 만들면 회중 분들의 연구 기록이 URL 만 알면 열린다.

### 경로

```
weeks/watchtower/2026-08-24.json                    공용
weeks/life-ministry/2026-08-24.json                 공용
users/{회원번호}/profile.json                        승인 기록
users/{회원번호}/talks/2026-08-24-3-학생연설.json     개인
```

파일명 앞이 주간이라 사전순 정렬이 곧 날짜순이다. Blob 의 `list()` 는 사전순으로
돌려주므로 별도 색인이 필요 없다.

배정 부분은 `절-제목` 을 파일명에 안전한 글자로 다듬어 쓴다. 이미 있는
`web/src/lib/talk-format.mjs` 의 `파일이름()` 과 같은 규칙을 쓴다. 규칙을 한 곳에
모아 두고 양쪽이 가져다 쓴다.

### 데이터 모양

공용 주간 자료.

```json
{
  "판": 1,
  "종류": "watchtower",
  "주간": "2026-08-24",
  "만든때": "2026-08-26T02:11:00Z",
  "자료": {}
}
```

`자료` 는 지금 API 가 돌려주는 것을 그대로 담는다. 모양을 바꾸지 않는다.

개인 연설 자료.

```json
{
  "판": 1,
  "주간": "2026-08-24",
  "배정": {},
  "프로필": {},
  "공개강연입력": null,
  "뼈대": {},
  "산출물": { "준비원고": "", "낭독대본": "", "큐카드": "", "점검표": "" },
  "시간": {},
  "고친때": "2026-08-26T02:40:00Z"
}
```

뼈대를 손으로 고친 것까지 담는다. 다시 들어오면 고친 상태에서 이어진다.

사용자.

```json
{ "판": 1, "회원번호": "1234567890", "닉네임": "동언", "승인된때": "2026-08-26T01:00:00Z" }
```

### 판 번호

세 가지 모두 `판` 을 맨 앞에 둔다. 앞으로 자료 모양이 바뀌었을 때 낡은 것을
알아보기 위해서다. 읽을 때 `판` 이 아는 값이 아니면 **저장된 게 없는 것으로 보고
새로 만든다.** 마이그레이션을 쓰지 않는다. 주간 자료는 다시 만들면 그만이고,
연설 자료는 사람마다 몇 건뿐이라 그 비용이 마이그레이션 코드보다 싸다.

## 4. 인증

### 흐름

```
브라우저                     우리 서버                      카카오
   │ "카카오로 로그인"
   ├──────────────────────────▶ /api/auth-start
   │                              state 생성·서명 쿠키에 보관
   │ ◀─────────────────────────── 302 ────────────────────▶ /oauth/authorize
   │            (사용자가 카카오에서 동의)
   │ ◀───────────────────────────────────────────────────── 302 code
   ├──────────────────────────▶ /api/auth-callback?code&state
   │                              state 검증
   │                              POST /oauth/token ────────▶ 액세스 토큰
   │                              GET /v2/user/me ──────────▶ 회원번호·닉네임
   │                              users/{회원번호}/profile.json 있나?
   │ ◀───── 예: 세션 쿠키 + 302 /
   │ ◀───── 아니오: 302 /invite (임시 쿠키에 신원만)
   │ 초대 코드 입력
   ├──────────────────────────▶ /api/auth-invite
   │ ◀───── 코드 맞으면 profile.json 생성 + 세션 쿠키
```

2026-08-26 에 공식 문서에서 확인한 엔드포인트다.

| 단계 | 메서드와 URL | 필수 파라미터 |
|---|---|---|
| 인가 코드 | GET `https://kauth.kakao.com/oauth/authorize` | `client_id`, `redirect_uri`, `response_type=code` |
| 토큰 | POST `https://kauth.kakao.com/oauth/token` | `grant_type=authorization_code`, `client_id`, `client_secret`, `redirect_uri`, `code` |
| 사용자 정보 | GET `https://kapi.kakao.com/v2/user/me` | Authorization 헤더의 액세스 토큰 |

### 카카오 토큰을 보관하지 않는다

신원을 확인하는 그 순간에만 쓰고 버린다. 로그인 뒤에 카카오 API 를 부를 일이
없기 때문이다. 남의 액세스 토큰을 보관하지 않으므로 새어 나갈 것이 줄어든다.

이 결정 때문에 로그아웃도 단순해진다. 카카오 쪽에 폐기할 토큰이 없으므로 우리가
발급한 쿠키 하나만 지우면 된다. 카카오계정과 함께 로그아웃은 쓰지 않는다.
그것을 쓰면 그 브라우저의 다른 카카오 서비스에서도 로그아웃되어 과하다.
따라서 로그아웃 리다이렉트 URI 도 등록하지 않는다.

### 세션

서명 쿠키 하나다. 서버에 세션 표를 두지 않으므로 서버리스와 맞는다.

- 값은 회원번호·닉네임·만료를 `SESSION_SECRET` 으로 HMAC-SHA256 서명한 것이다
- `HttpOnly; Secure; SameSite=Lax; Path=/`
- 만료는 발급 시점부터 30일이다. 쓸 때마다 연장하지 않는다. 30일이 지나면
  다시 로그인한다
- `SESSION_SECRET` 을 바꾸면 전원 로그아웃된다. 사고가 아니라 설계다

`state` 는 CSRF 를 막는다. 인가 시작 때 만들어 서명 쿠키에 담고 콜백에서 맞는지
본다. 이 쿠키와 `/invite` 로 넘길 때 쓰는 임시 신원 쿠키는 둘 다 **10분**이면
충분하다. 로그인 흐름 안에서만 살아 있으면 되기 때문이다.

**서명 쿠키는 모두 같은 함수·같은 비밀로 만들어진다. 용도를 담긴 값 안에 넣고
읽을 때 검증하지 않으면, 짧게 쓰고 버리라고 만든 신원 쿠키를 그대로 세션 쿠키
자리에 넣어도 통과한다.** 페이로드 모양이 같고 서명이 같은 비밀로 만들어지기
때문이다. 그래서 모든 서명 토큰은 `용도`(`'세션'`|`'신원'`)를 페이로드 안에 담고,
읽는 쪽은 기대하는 용도를 명시해서 검증한다. 용도가 다르면 서명이 맞아도 거부한다.
주석으로 "세션이 아니다"라고 적어 두는 것은 강제가 아니므로 세지 않는다.

### 초대 코드

회원번호는 그 사람이 로그인해 봐야 알 수 있는데 허용 명단은 미리 있어야 한다.
닭과 달걀이다. 초대 코드로 푼다.

형제가 회중 분들께 코드 하나를 알려 준다. 첫 로그인 때 그 코드를 넣으면 회원번호가
`users/{회원번호}/profile.json` 으로 박힌다. 이후로는 코드 없이 로그인된다.
코드를 바꿔도 이미 승인된 사람은 영향받지 않는다.

## 5. 화면

### 새 화면 셋

- `/login` — 카카오 버튼 하나. 로그인 안 됐으면 여기로 보낸다
- `/invite` — 첫 로그인 때 초대 코드 입력
- `/my` — 내가 만든 원고 목록. 상단 막대에 항목이 하나 는다

상단 막대 오른쪽 끝에 닉네임과 로그아웃이 붙는다.

### 생활과 봉사·파수대

겉모습은 그대로고 속이 달라진다.

```
"준비" 클릭
  → 저장된 게 있나?
      있으면 → 즉시 표시. 진행률 게이지 없음. 토큰 안 씀
      없으면 → OpenAI 호출 → 저장 → 표시
```

저장된 것을 보여 줄 때 위에 안내 띠가 붙는다.

```
┌────────────────────────────────────────────┐
│ 2026-08-26 에 만들어진 답변입니다.  [다시 만들기] │
└────────────────────────────────────────────┘
```

다시 만들기는 확인 대화를 거친다.

> 이번 주 교재 답변이 이미 있습니다. 다시 만들면 이전 답변은 사라지고, 회중의
> 다른 분들께도 새 답변이 보이게 됩니다. 계속할까요?

공용본이 하나뿐이므로 다시 만들면 다른 사람 것도 같이 바뀐다. 회중 몇 분이 서로
아는 사이이므로 확인 문구로 충분하다고 보았다. 문구에 "다른 분들께도" 를 넣은
이유가 이것이다.

확인 대화는 `window.confirm` 이 아니라 shadcn `AlertDialog` 로 만든다. 브라우저
기본 대화상자는 화면 자동 검증 도구를 멈추게 해서 확인이 불가능해진다.

### 연설

배정을 고르면 저장된 게 있는지 먼저 본다. 있으면 뼈대와 산출물이 복원되어
뼈대 만들기부터 다시 할 필요가 없다. 화면을 나갔다 돌아와도 그대로다.

## 6. API

### 기존 여섯

전부 세션 검증이 붙는다. 세션이 없으면 401 을 돌려주고 화면이 `/login` 으로 보낸다.

- `GET /api/options` — 그대로
- `GET /api/watchtower?date=` — 저장된 것을 먼저 본다
- `GET /api/life-ministry?date=` — 저장된 것을 먼저 본다
- `GET /api/talk-assignments?date=&profile=` — 그대로
- `POST /api/talk-outline` — 그대로
- `POST /api/talk-draft` — 만든 뒤 저장한다

### 새로 넷 (인증)

- `GET /api/auth-start` — 카카오로 보낸다
- `GET /api/auth-callback` — 토큰 교환·신원 확인·세션 발급
- `POST /api/auth-invite` — 초대 코드 확인·승인 기록
- `POST /api/auth-logout` — 쿠키 삭제

### 새로 다섯 (자료)

- `POST /api/watchtower` — 다시 만들기
- `POST /api/life-ministry` — 다시 만들기
- `GET /api/my-talks` — 내 원고 목록
- `GET /api/my-talk?key=` — 하나 조회
- `DELETE /api/my-talk?key=` — 하나 삭제

`key` 는 `users/{회원번호}/talks/` 아래의 파일 이름이다. 경로 전체가 아니다.
서버가 세션의 회원번호를 앞에 붙여 실제 경로를 만든다. **브라우저가 보낸 값에
`/` 나 `..` 가 있으면 거부한다.** 그러지 않으면 남의 폴더를 읽을 수 있다.

**다시 만들기를 POST 로 분리한 이유가 있다.** GET 에 `force=1` 을 붙이면 브라우저
새로고침이나 미리 가져오기로 의도치 않게 OpenAI 호출이 나갈 수 있다. 돈 드는
동작을 GET 에 두지 않는다.

엔드포인트가 평평한 이름인 이유도 있다. `vercel.json` 의 `functions` 글롭이
`api/*.js` 라 중첩 폴더를 잡지 못한다. 기존 `api/` 구조와도 맞는다.

## 7. 오류 처리

| 상황 | 처리 |
|---|---|
| 세션 없음·만료 | 401. 화면이 `/login` 으로 보낸다 |
| `state` 불일치 | 로그인 거부. 다시 시도하라고 안내한다 |
| 카카오가 로그인을 거절함(`error`) | 콜백의 `error`·`error_description` 을 그대로 보여 준다. 9절의 미확인 위험을 가를 유일한 단서다 |
| 카카오 토큰 교환 실패 | 카카오가 준 오류 코드를 그대로 보여 준다. `KOE004`·`KOE006` 은 설정 문제라 형제가 알아야 고칠 수 있다 |
| 승인 안 된 사람 | `/invite` 로 보낸다 |
| 초대 코드 틀림 | 그 자리에서 알린다. 몇 번 틀렸는지는 세지 않는다 |
| Blob 읽기 실패(주간·연설 자료) | 저장된 게 없는 것으로 보고 새로 만든다. 저장은 편의이지 필수가 아니다 |
| 초대 승인 기록의 Blob 쓰기 실패 | 조용히 넘기지 않는다. "저장소에 연결하지 못했습니다" 처럼 구분되는 오류로 알린다. 이 쓰기가 그 사람이 누구인지를 정하기 때문이다 |
| 그 밖의 Blob 쓰기 실패(주간·연설 자료) | 결과는 그대로 보여 주고 저장 실패만 조용히 넘긴다. 만든 것을 잃지 않는 쪽이 낫다 |
| 동시에 다시 만들기 | 나중 것이 이긴다. 회중 몇 사람 규모에서 굳이 막지 않는다 |

**"읽기 실패를 조용히 넘긴다"는 규칙은 캐시처럼 못 찾으면 새로 만들면 그만인
자료에만 쓴다. 누군가의 신원이나 접근 권한을 정하는 읽기에는 쓰지 않는다.**
4단계에서 개인 연설 자료를 `users/{회원번호}/talks/…` 로 관리할 때도, 같은
`읽기` 함수가 "이 파일이 이 회원의 것인가"를 가르는 자리에 쓰이게 된다. 그
자리에서 읽기 실패를 "없는 것"으로 보는 것과 "권한 없음"으로 보는 것은 전혀
다른 문제이므로 이 절의 예외를 반드시 다시 살핀다.

## 8. 시험

이 저장소에는 화면 컴포넌트 시험이 없다. 순수 함수를 떼어 내 `node --test` 로
덮는 방식을 이어 간다.

떼어 내 덮을 것.

- 세션 쿠키 서명과 검증 — 위조·만료·변조를 잡는지
- 저장 경로 만들기 — 배정 이름의 위험한 글자, 길이 자르기
- 저장된 자료의 모양 확인 — 낡은 모양을 만나면 새로 만들게 하는지

카카오와 Blob 은 바깥이므로 시험에서 부르지 않는다. 그 둘을 부르는 자리를
얇은 함수로 감싸고, 감싼 것을 갈아 끼워 시험한다.

`npm run smoke:web` 에 `/login`·`/invite`·`/my` 를 더한다.

## 9. 위험과 미결

**로그인이 아예 막힐 수 있다.** 카카오 앱이 개발·테스트 상태일 때 팀원이 아닌
사람도 로그인할 수 있는지가 공식 문서에 나오지 않는다. 2026-08-26 기준으로
`kakaologin/common` 과 `kakaologin/prerequisite` 를 확인했으나 다루지 않는다.
제한이 있다면 회중 분들을 팀원으로 등록하거나 앱을 배포 상태로 올려야 한다.
**형제가 카카오 디벨로퍼스 콘솔에서 확인해야 하고, 막히면 이 기능 전체가 못 간다.**
이 위험을 가릴 유일한 단서가 카카오 콜백의 `error`·`error_description` 이므로,
콜백은 이 값을 반드시 그대로 화면에 보여 준다. 감춰 버리면 "팀원이 아님"과
"redirect URI 설정 오류"와 "사용자가 취소함"을 구분할 방법이 없어진다.

**로그인은 `APP_BASE_URL` 과 같은 호스트에서만 된다.** `redirect_uri` 를
`APP_BASE_URL` 로 고정하기 때문이다(4절). 프리뷰 배포(예:
`preview-xxx.vercel.app`)에서 인가를 시작하면 카카오는 여전히 프로덕션
호스트로 돌아오고, 프로덕션에는 그 로그인 시도의 `jw_state` 쿠키가 없으므로
"로그인 요청이 확인되지 않았습니다"로 실패한다. 이 메시지는 호스트가 다르다는
것을 말해 주지 않으므로, 프리뷰 배포에서 로그인을 시험하다가 이 위 항목의
위험과 헷갈리기 쉽다. 프리뷰 배포에서는 로그인이 되지 않는다는 것을 미리 안다.

**Blob 저장소를 Public 으로 만들면 되돌릴 수 없다.** 만들 때 `Private` 를 골라야
한다. 잘못 만들면 지우고 다시 만드는 수밖에 없다.

**회원 탈퇴 웹훅을 아직 안 만든다.** 카카오 콘솔이 경고하는 항목이다. 회중 분이
카카오에서 연결을 끊으면 우리가 보관 중인 그분 자료도 지워야 한다. 남의 자료를
보관하기로 한 이상 언젠가는 해야 한다. 이번 범위 밖으로 두되 잊지 않는다.

**다시 만들기에 횟수 제한이 없다.** 승인된 사람은 누구나 토큰을 계속 쓸 수 있다.
아는 분들 몇이라 지금은 두지 않는다. 필요해지면 하루 몇 회 같은 제한을 넣는다.

**비밀값 취급.** `.env.example` 은 Git 에 올라가므로 실제 값을 넣지 않는다.
2026-08-26 에 한 번 실제 값이 그 파일에 들어갔다가 커밋 전에 `.env` 로 옮겼다.

## 10. 구현 순서

인증이 먼저다. 저장은 "누구의 것인가" 가 정해져야 얹힌다.

1. **저장소 감싸기와 세션** — Blob 을 부르는 얇은 함수, 세션 쿠키 서명·검증.
   여기까지는 화면이 없어도 `node --test` 로 덮인다
2. **인증 네 엔드포인트와 두 화면** — 로그인·초대. 이 단계가 끝나면 로그인해야
   기존 화면을 쓸 수 있게 된다
3. **주간 자료 공유** — 읽기에 캐시를 태우고 다시 만들기를 POST 로 붙인다.
   토큰 절감이 여기서 나온다
4. **연설 자료 보관과 `/my` 화면** — 저장·복원·목록·삭제

1과 2가 끝나면 배포해도 동작한다. 3과 4는 그 위에 더한다.

## 11. 환경 변수

이 표의 넷은 전부 필수다. 값이 비었거나(`SESSION_SECRET` 은 32자보다 짧아도)
서버는 **모든 요청을 거부한다.** 조용히 넘어가 위조 가능한 세션이나 빈
`client_id` 로 카카오에 요청하는 쪽이 훨씬 위험하기 때문이다. 시끄럽게 막혀야
바로 눈에 띄어 고칠 수 있다.

| 이름 | 출처 |
|---|---|
| `KAKAO_REST_API_KEY` | 카카오 · 앱 설정 → 앱 → REST API 키 |
| `KAKAO_CLIENT_SECRET` | 카카오 · 카카오 로그인 → 고급 → Client Secret |
| `SESSION_SECRET` | `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` |
| `INVITE_CODE` | 형제가 정한다. 시도 횟수 제한이 없으므로 무작위 값을 쓴다(`.env.example` 참고) |

Blob 자격 증명은 저장소를 프로젝트에 연결하면 Vercel 이 자동으로 넣는다.

카카오 콘솔에서 등록할 Redirect URI 는 둘이다.

```
https://jw-assistant-seven.vercel.app/api/auth-callback
http://localhost:3000/api/auth-callback
```
