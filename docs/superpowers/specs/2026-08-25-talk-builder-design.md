# 연설준비 설계 — 배정에서 원고까지

- 작성일은 2026-08-25이다.
- 현행 운영 정본은 `docs/핵심-운영-인수인계.md`이며 이 문서는 그 위에 새 기능 하나를 더한다.
- 이 기능은 배포 가능하다. 이유는 5절에 있다.

## 1. 무엇을 만드는가

웹앱에 `연설준비` 화면을 새로 만든다. 그 주 「그리스도인 생활과 봉사」 교재에서 배정
항목을 뽑아 형제가 고르게 하고, 화자의 신원과 문체를 반영해 원고의 뼈대를 제안한 뒤,
형제가 뼈대를 확인하면 대사를 채워 네 가지 산출물을 만든다.

목표 산출물은 이미 실물로 존재한다. `activities/talks/2026-08-24/` 의 두 파일이다.
그 밀도와 형식을 기계로 재현하는 것이 이 기능의 성공 기준이다.

지원하는 연설은 셋이다.

| 종류 | 자료 출처 | 자격 |
|---|---|---|
| 생활과 봉사 학생 과제 | 그 주 교재 | 시연은 자매도 가능. 학생 연설은 형제만 |
| 그리스도인 생활 부분 연설 | 그 주 교재 | 임명된 형제만 |
| 일요일 공개강연 | 형제가 붙여넣은 공식 개요 | 임명된 형제만 |

자유 주제 연설은 이번 범위가 아니다.

## 2. 확인된 사실

전부 2026-08-25에 실측했다.

### 「읽가」 — 연설 기술 교본

- 정식 이름은 「읽고 가르치는 기술을 발전시키십시오」다.
- 20과이며 docid는 `1102018441`(1과)부터 `1102018460`(20과)까지 연속이다.
  `1102018461`은 이 브로슈어가 아니다.
- 조회 URL 형식은 `https://wol.jw.org/ko/wol/d/r8/lp-ko/<docid>` 이고 조회일은 2026-08-25다.

- 본문 합계는 11,738자다. 토큰으로 약 7,336이며 과당 평균 367이다.
- 20과 목록은 이렇다. 1 효과적인 서론, 2 자연스럽게 말하기, 3 질문 사용하기,
  4 성구 소개하기, 5 정확한 낭독, 6 성구를 명확하게 적용하기,
  7 정확하고 믿을 수 있는 자료 사용하기, 8 비유를 사용하여 가르치기,
  9 시각 자료를 올바로 사용하기, 10 목소리 조절, 11 열정, 12 따뜻함과 감정 이입,
  13 실용적인 가치를 분명하게 알려 주기, 14 요점을 명확히 강조하기,
  15 확신 있게 말하기, 16 긍정적이고 격려적인 말,

- 정식 이름은 「사람들을 사랑하고 제자로 삼으십시오」다.
- 3과 docid는 `1102023303`이고 본문은 1,200자, 약 750토큰이다.

- **전체 과 수는 아직 확인하지 않았다.** 3과 하나만 실측했다. 매니페스트 생성기를

### 「익」을 쓰지 않는 이유

「신권 전도 학교 교육에서 얻는 유익」은 2001년 구판이다. 47과 docid `1102001118`을
실측하니 한 과가 3,771토큰이었다. 「읽가」 한 과의 열 배다. 그리고 현행 교재가

### 그 주 교재의 구조

2026년 8월 24-30일 주 docid `202026248`을 `src/wol-html.mjs`의 `요소들`로 파싱한 결과다.

```
[h2] 야외 봉사에 힘쓰십시오
[h3] 4. 대화 시작하기
[p]  (4분) 호별 방문. 9월 특별 활동의 주제를 근거로 대화를 시작하고
     성서 연구를 제안한다. (「랑제」 3과 요점 4)
     링크: 「랑제」 3과 요점 4 -> /ko/wol/pc/r8/lp-ko/202026248/6/0
[h3] 6. 연설
[p]  (5분) 「웹성해」 기사 6—주제: 예레미야 29:11의 의미는 무엇입니까? (「읽가」 1과)
[h2] 그리스도인 생활
[h3] 7. 여호와는 자신의 종들에게 희망을 주십니다
[p]  (10분) 토의.
```

`h3`가 `번호. 제목`이고 뒤따르는 첫 `p`가 `(N분) 형태. 설명. (지정 요점)`이다.
번호, 제목, 시간, 봉사 형태, 지정 요점이 전부 기계로 읽힌다.

지정 요점 링크는 `/pc/` 형식이며 `resolveRedirect`로 `/d/...#h=` 로 바뀐다.
`「랑제」 3과 요점 4` 는 `1102023303#h=16:0-17:0` 으로 해석된다.

### 공개강연 개요는 WOL에 없다

`공개 강연 개요`로 WOL을 검색하면 결과가 3건이고 전부 연감과 과거 파수대의 언급이다.
개요 본문은 없다. 개요는 회중에 배부되는 자료다. 따라서 형제가 붙여넣는 경로 외에
개요를 얻을 방법이 없다.

### 기존 파서의 한계

`src/ministry-meeting.mjs`의 `parseMinistryMeeting`은 `영적 보물 찾기` 질문과
`회중 성서 연구`만 뽑는다. 야외 봉사 배정과 그리스도인 생활 항목은 뽑지 않는다.
확장이 필요하다.

## 3. 화면 흐름

네 걸음이다. 봉사인도와 같이 한 번에 끝내지 않는다. 형제가 뼈대를 확인해야 하기 때문이다.

### ① 배정 고르기

```
GET /api/talk/assignments?date=YYYY-MM-DD
```

그 주 교재를 받아 배정 항목을 카드로 돌려준다. 각 카드는 번호, 제목, 시간, 봉사 형태,
지정 요점, 교재 원문을 갖는다. 공개강연을 고르면 개요를 붙여넣는 칸이 열린다.

교재를 못 받으면 그 사실을 표시하고 멈춘다. 빈 목록을 조용히 돌려주지 않는다.

### ② 화자 확인

프로필은 브라우저에 남는다. 서버에 저장하지 않는다.

| 항목 | 값 | 쓰임 |
|---|---|---|
| 성별 | 형제 / 자매 | 배정 가능 여부를 가른다 |
| 연령 | 숫자 | 예화 소재와 어휘를 정한다 |
| 임명 | 장로 / 봉사의 종 / 미임명 | 배정 가능 여부를 가른다 |
| 파이오니아 | 예 / 아니오 | 예화와 경험담의 소재를 정한다. 자격에는 영향이 없다 |
| 스타일 | 논리형 / 설득형 / 이야기형 / 따뜻한 격려형 / 질문형 | 구성과 도입부 형태를 정한다 |
| 문체 견본 | 지난 원고 본문 | 문장 길이, 예화 취향, 성구 도입 방식을 잡는다 |

성별과 임명은 톤 조절 항목이 아니라 게이트다. 4절에서 자세히 다룬다.

### ③ 뼈대 확인

```
POST /api/talk/outline
```

AI가 구성만 돌려준다. 대사는 아직 쓰지 않는다.

- 구간 목록. 각 구간의 이름, 시작과 끝 시각, 그 구간의 목적.
- 읽을 성구의 주소. 본문은 아니다.
- 지정 요점을 어느 구간에서 드러낼지.
- 시연이면 등장인물과 상황과 준비물.
- 연설이면 소제목과 각 소제목의 요점.

형제가 화면에서 고친다. 구간을 지우거나 시간을 옮기거나 성구를 바꿀 수 있다.

### ④ 살 채우기

```
POST /api/talk/draft
```

확정된 뼈대를 받아 대사를 채우고 원고 구조체 하나를 돌려준다. 화면은 그 구조체에서
산출물 네 개를 만들어 탭으로 보여 준다.

## 4. 자격 게이트

성별과 임명이 고를 수 있는 배정을 좁힌다. 화면에서 못 하는 배정을 아예 못 고르게 한다.

| 배정 | 형제 | 자매 |
|---|---|---|
| 대화 시작하기 · 다시 방문하기 · 성서 연구 (시연) | 가능 | 가능. 보조자가 필요하다 |
| 성경 낭독 | 가능 | 불가 |
| 학생 연설 | 가능 | 불가 |
| 그리스도인 생활 부분 | 장로와 봉사의 종만 | 불가 |
| 공개강연 | 장로와 봉사의 종만 | 불가 |

파이오니아 여부는 이 표에 영향을 주지 않는다. 봉사의 형태이지 임명이 아니기 때문이다.

막힌 배정 카드는 회색으로 두고 왜 막혔는지 한 줄로 표시한다. 조용히 숨기지 않는다.

**출판물 근거 미확인 — 내 정리임.** 위 표는 형제가 알려 준 회중 관행과 교재의 배정
형태에서 정리한 것이다. 임명 자격에 관한 지침서 원문을 근거로 대지 않았다.
회중의 실제 마련과 다르면 형제가 표를 고칠 수 있어야 한다.

## 5. 왜 배포 가능한가

`docs/핵심-운영-인수인계.md`에 기록된 대로 WOL `/pc/` 경로는 Vercel에서 반복해서
`ETIMEDOUT`이 난다. `/d/` 경로만 안정적이다.

이 기능이 실행 시점에 받는 것은 그 주 교재 `/d/` 하나뿐이다. 「읽가」와 「랑제」는
매니페스트에서 오고 매니페스트는 저장소에 커밋된다. 지정 요점의 `/pc/` 해석이
실패해도 매니페스트의 과 단위 요점으로 대신할 수 있다. 전체 실패로 번지지 않는다.

따라서 `api/*.js` 어댑터를 만들고 `vercel.json`에 경로를 더한다.

## 6. 산출물 네 개를 한 번에 만든다

AI가 만드는 것은 원고 구조체 **하나**다. 산출물 네 개는 코드가 그것에서 깎아 낸다.

```
원고구조체 = {
  제목, 종류, 배정시간(초), 지정요점,
  설정: { 등장인물[], 상황, 준비물[] },
  구간: [ { 이름, 시작초, 끝초, 목적 } ],
  대사: [ { 구간, 화자, 말, 동작, 요점표시 } ],
  단락: [ { 소제목, 요점[], 예화, 성구주소[] } ],
  성구: [ { 주소, 본문 } ],
  축약순서: [ { 순위, 대상, 사유 } ],
  출처: [ { 제목, url, 조회일 } ],
}
```

| 산출물 | 만드는 방법 |
|---|---|
| 준비용 원고 | 구조체 전체를 펼친다 |
| 낭독용 대본 | `대사`의 `말`과 `동작`만 뽑는다 |
| 연단 큐카드 | `구간`과 `단락.요점`과 `성구.주소`만 뽑는다 |
| 자기 점검표 | `요점표시`가 붙은 대사를 모아 `지정요점`과 대조한다 |

이렇게 하면 비용이 4분의 1이고, 네 산출물이 서로 어긋나는 것이 구조적으로 불가능하다.

시연은 `대사`를 쓰고 `단락`을 비운다. 연설은 반대다. 공개강연은 개요의 소제목이
그대로 `단락.소제목`이 된다.

## 7. 정확성 규칙

### 성구

**AI는 성구 문장을 쓰지 않는다. 주소만 돌려준다.** 서버가 `parseReference`로 주소를
해석하고 `core/bible/text/`에서 실제 문자열을 읽어 `성구.본문`을 채운다.

주소가 해석되지 않으면 그 칸을 비우고 `성구 자동 확인 실패`를 표시한다. AI가 쓴
성구 문장을 그대로 쓰는 경로는 코드에 만들지 않는다. 봉사인도와 같은 방식이다.

`대사.말` 안에 성구를 낭독하는 대목이 있으면, 그 자리에는 자리표시자를 두고 서버가
로컬 본문으로 치환한다. AI가 인용부호 안에 성경 문장을 직접 쓰면 그 대사를 거절한다.

### 출판물

「읽가」와 「랑제」의 요점은 원문 그대로 인용하고 링크와 조회일을 `출처`에 남긴다.
출판물 근거를 대지 못한 문장에는 `출판물 근거 미확인 — 내 정리임.` 을 붙인다.

공개강연 개요는 붙여넣은 원문을 그대로 둔다. 개요의 문장을 고치지 않는다.
우리가 더하는 것은 예화, 청중 적용, 시간 배분뿐이다.

### 언어

한국어 문장은 마침표로 끝낸다. 문장 끝에 콜론을 쓰지 않는다. 한국어 이외의 문자
체계가 섞이지 않도록 기존 답변 생성과 같은 정규화를 적용한다.

## 8. 시간은 코드가 센다

AI에게 시간을 묻지 않는다. 대사와 단락의 글자 수를 세어 계산한다.

```
낭독초 = 글자수 / (분당글자수 / 60)
```

분당 글자수는 형제가 조절하는 값이며 기본은 320이다. 사람마다 다르고 실제로 읽어 본
뒤에 맞춰 가야 하기 때문이다. 이 값은 프로필에 저장한다.

동작 지시는 글자 수에서 빼고 대신 지시 하나당 1.5초를 더한다. 성구 낭독은 다른
대사보다 느리므로 분당 글자수의 0.85배를 적용한다. 두 계수 모두 화면에서 고칠 수 있다.

배정 시간을 넘으면 `축약순서`를 순위대로 적용했을 때의 예상 시간을 함께 보여 준다.

> 지금 4분 38초입니다. 배정은 4분입니다.
> 축약 1순위를 빼면 4분 12초, 2순위까지 빼면 3분 51초입니다.

자동으로 줄이지는 않는다. 무엇을 뺄지는 형제가 정한다.

        "요점": "서론에서 듣는 사람의 흥미를 불러일으키고, 말할 내용이 무엇인지 밝히고, 듣는 사람이 왜 관심을 가져야 하는지 알려 주어야 합니다.",
        "docid": 1102018441

    "제목": "사람들을 사랑하고 제자로 삼으십시오",

담는 것은 과 번호와 제목과 요점 한 줄과 docid다. 과 본문 전체는 담지 않는다.

기준선은 「읽가」 20과다. 「랑제」 기준선은 생성기를 처음 돌려 확정한 뒤 여기에 적는다.
추출 수가 기준선보다 줄면 스크립트가 경고하고 종료 코드 1로 끝난다. 파서가 조용히
얇아지는 것을 막는 기존 원칙과 같다.

### 본문 저장 규칙의 예외

이 저장소는 지금까지 출판물 본문을 저장하지 않았다. `service-topics.json`도
`wol-reference-map.json`도 라벨과 링크만 담는다.

이 매니페스트는 과당 한 문단씩 실제 출판물 문장을 담는다. 예외를 두는 이유는 셋이다.

1. 이 한 문단이 그 과의 전부가 아니다. 「읽가」 1과 본문은 572자이고 요점은 그중
   약 100자다. 목차의 설명문에 가깝다.
2. 이것이 없으면 원고를 만들 때마다 과를 실시간으로 조회해야 하고, Vercel에서는
   요청마다 20번의 WOL 호출이 붙어 배포가 사실상 불가능해진다.
3. 요점 문단은 AI에게 "이 원고가 어긋나면 안 되는 기술 규칙 20가지" 를 주는 가장 짧은
   방법이다. 우리가 요약하면 정확성이 떨어지고, 전문을 넣으면 7,336토큰이 든다.

매니페스트의 각 과에 `docid`를 함께 남겨 원문을 언제든 대조할 수 있게 한다.
2026-08-25에 형제의 승인을 받은 예외다.

## 10. 토큰 예산

원고 하나에 약 6,000에서 8,000 토큰이다.

| 항목 | 토큰 |
|---|---|
| 「읽가」 20과 요점 목록 | 약 900 |
| 지정 요점의 과 전문 1개 | 약 400에서 750 |
| 교재 배정 원문 | 약 400 |
| 프로필과 문체 견본 | 약 1,500 |
| 뼈대 생성 응답 | 약 800 |
| 대사 생성 응답 | 약 2,000 |

「익」 전권을 넣는 설계였다면 약 190,000 토큰이었다.

가이드 블록은 프롬프트의 맨 앞 고정 위치에 둔다. 프롬프트 캐시가 걸려 반복 호출
비용이 떨어진다.

**전권을 프롬프트에 넣는 경로는 코드에 만들지 않는다.** 실수로 190,000 토큰을 태우는
것이 구조적으로 불가능해야 한다.

## 12. 오류 처리

| 상황 | 동작 |
|---|---|
| 그 주 교재 조회 실패 | 표시하고 멈춘다. 빈 목록을 돌려주지 않는다 |
| 교재에서 배정을 하나도 못 뽑음 | 경고하고 교재 원문 링크를 보여 준다 |
| 지정 요점 `/pc/` 해석 실패 | 매니페스트의 과 단위 요점으로 대신하고 그 사실을 표시한다 |
| 개요 붙여넣기가 비어 있음 | 공개강연 생성을 막는다 |
| 자격에 맞지 않는 배정 선택 | 카드를 회색으로 두고 사유를 표시한다 |
| OpenAI 키 없음 또는 호출 실패 | 교재 원문과 지정 요점으로 만든 결정론적 뼈대를 돌려준다 |

| AI가 성구 문장을 직접 씀 | 그 대사를 거절하고 다시 요청한다 |
| 배정 시간 초과 | 원고는 그대로 두고 축약 제안을 함께 보여 준다 |

어느 경우에도 성구 문장은 `core/bible/text/`에서만 온다.

## 13. 화면

상단 내비게이션과 홈 카드에 `연설준비`를 더한다. 화면은 네 부분이다.

1. 배정 영역. 주를 고르면 배정 카드가 뜬다. 자격에 안 맞는 카드는 회색이다.
2. 화자 영역. 프로필을 입력하고 브라우저에 저장한다.
3. 뼈대 영역. 구간표를 보여 주고 고칠 수 있게 한다. 예상 시간을 실시간으로 센다.
4. 산출물 영역. 탭 네 개. 각각 `복사`와 `내려받기`.

`복사`는 그 산출물 본문만 복사한다. 선정 이유나 디버그 정보는 넣지 않는다. 기존
`답변 복사`의 규칙과 같다.

`내려받기`는 브라우저가 마크다운 파일로 저장한다. 서버에 아무것도 쓰지 않는다.
파일 이름은 `<날짜>-<배정제목>-<산출물>.md` 다.

진행률 게이지는 만들지 않는다.

## 14. 테스트

전부 픽스처 기반이며 네트워크를 타지 않는다.

- 배정 파서. `h3` 번호와 제목, 뒤따르는 `p`의 시간과 형태와 지정 요점을 뽑는다.
  야외 봉사와 그리스도인 생활 두 절을 각각 검사한다.
- 기존 `parseMinistryMeeting` 반환값이 그대로인 것을 검사한다. 회귀 방지다.
- 교본 매니페스트 기준선. 「읽가」가 20과보다 적으면 실패한다.
- 자격 게이트. 자매 프로필이 학생 연설과 공개강연을 막는지, 미임명 전도인이
  그리스도인 생활 부분을 막는지 검사한다.
- 산출물 파생. 구조체 하나에서 네 산출물이 나오고, 큐카드의 요점이 원고에 전부
  존재하는 것을 검사한다.
- 시간 계산. 글자 수와 동작 지시 개수로 초를 계산하고, 축약 순위 적용 후의 시간이
  줄어드는 것을 검사한다.
- 성구 치환. 유효한 주소는 로컬 본문으로 채워지고, 잘못된 주소는 거절되며,
  AI가 인용부호 안에 쓴 성경 문장이 절대 통과하지 않는 것을 검사한다.
- 키가 없을 때 뼈대가 비어 있지 않고 결정론적 표시가 붙는 것을 검사한다.

기존 테스트 위에 더한다.

## 15. 하지 않는 것

- 로그인, 계정, 사용자별 저장, 작업내역. 별도 설계로 다룬다.
- 노션 저장.
- 「익」 연동.
- 자유 주제 연설.
- 서버에 산출물 저장. 1단계는 화면과 복사와 내려받기뿐이다.
- 원고 자동 축약. 무엇을 뺄지는 형제가 정한다.
- 외부 npm 의존성 추가.
