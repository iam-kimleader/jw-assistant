# jw-assistant 설계 문서

- **작성일** 2026-07-29
- **사용자** 김동언 (35세, 여호와의 증인, 광주양림회중)
- **상태** 승인됨

> 이 문서는 로컬 도구만 계획했던 초기 설계 기록이다. 이후 웹 서비스와 AI 답변 기능이
> 구현되어 3절과 10절의 웹 UI 제외 전제는 더 이상 현행이 아니다. 현재 운영 기준은
> `docs/핵심-운영-인수인계.md`를 따른다.

---

## 1. 목적

김동언 형제가 성경을 올바로 이해하여 여호와 하느님을 더 자세히 알아가고 영적으로 장성하도록 돕는 개인용 도구를 만든다.

핵심 성공 기준은 하나다. **연구가 소모되지 않고 축적되는가.** 이번 주에 이해한 것이 3년 뒤에도 찾아지고, 다음 연구가 그 위에서 시작되어야 한다. 단발성 답변만 잘하는 도구는 이 기준에서 실패한 것으로 본다.

## 2. 다루는 활동

1. 집회 준비 — 파수대 연구 예습, 우리의 그리스도인 생활과 봉사 모임 과제, 주간 성경 읽기
2. 주제별 심층 연구 — 특정 교리·성구를 파고들어 정리
3. 야외 봉사 준비 — 대화 준비, 성구 선택, 예상 반론 대응
4. 개인 성경 통독 — 매일 읽기 진도와 일지
5. 공개강연 준비 — 개요 기반 원고 구성

## 3. 형태와 자료 출처

- **형태** 로컬 마크다운 저장소 + Claude Code 슬래시 명령어. 서버도 웹 UI도 만들지 않는다.
- **성경 본문** 사용자가 소유한 `nwtsty_KO.jwpub` (2024년판 신세계역 연구용 성경, 122MB)에서 추출해 로컬 보관
- **출판물** 필요할 때 wol.jw.org에서 조회하고 URL과 조회 날짜를 기록

### 3.1 jwpub 구조 (확인 완료)

```
nwtsty_KO.jwpub  (ZIP)
├── manifest.json          name: "nwtsty_KO.jwpub", contentFormat: "z-a"
└── contents  (ZIP, 703 항목)
    ├── nwtsty_KO.db       SQLite, 56MB  ← 본문·각주·상호참조·연구노트·용어집
    └── *.jpg / *.svg      삽화 702개
```

`contentFormat: "z-a"` 는 문서 내용이 zlib 압축 후 AES 암호화되어 있음을 뜻한다. 무료 배포 출판물을 본인이 내려받아 개인 연구용으로 로컬에서 사용하는 것이며, 재배포하지 않는다.

## 4. 구조 — 지식 코어 + 활동 워크플로

두 층으로 나눈다.

- **코어(영구)** 계속 다듬어지는 자산. 성경 본문, 성구 노트, 주제 노트, 원어 노트
- **활동(시점)** 날짜가 붙은 산출물. 주간 예습, 강연 원고, 봉사 준비물, 통독 일지

활동은 코어를 **읽어서** 준비하고, 끝나면 새로 얻은 통찰을 코어로 **승격**한다. 이 승격 단계가 설계의 핵심이며, 이것이 빠지면 단순한 활동별 폴더 구조와 다를 바가 없어진다.

### 4.1 디렉토리

```
jw-assistant/
├── CLAUDE.md                    # 프로젝트 규칙 (§6 정확성 규칙을 여기에 못 박음)
├── checklist.md                 # 진행 체크리스트
├── context-notes.md             # 결정과 이유 기록
├── package.json                 # 검증 스크립트 실행용
│
├── core/                        # ── 영구 자산
│   ├── bible/
│   │   ├── index.md             # 66권 목록, 약어, 장·절 수, 기준 절 개수
│   │   ├── text/40-마태.md       # 본문 — 한 줄이 한 절
│   │   ├── notes/40-마태.md      # 연구 노트 + 각주 — 절 기준
│   │   └── refs/40-마태.tsv      # 상호 참조 — 절 → 관련 절
│   ├── verses/                  # 성구 노트   예) 마태-24-14.md
│   ├── topics/                  # 주제 노트   예) 왕국.md, 부활.md
│   ├── words/                   # 원어 노트   예) 네페시.md, 아가페.md
│   └── glossary.md              # nwtsty 용어집
│
├── activities/                  # ── 시점 산출물
│   ├── meetings/2026-08-03/     # 집회 준비
│   ├── talks/                   # 공개강연
│   ├── ministry/                # 야외 봉사
│   └── reading/                 # 통독 일지
│
├── profile/
│   ├── me.md                    # 회중, 현재 맡은 과제, 관심 주제
│   └── progress.md              # 통독 진도, 영적 목표
│
├── scripts/                     # 추출·검증 스크립트
│   ├── extract-jwpub.mjs
│   ├── verify-bible.mjs
│   └── verify-links.mjs
│
└── docs/superpowers/specs/      # 설계 문서
```

폴더 이름은 영문, 파일 이름과 내용은 한국어로 쓴다. 경로에 한글이 섞이면 스크립트에서 잔고장이 생기므로 폴더만 영문으로 둔다.

### 4.2 본문 저장 형식

권당 파일 하나, 한 줄이 한 절이다.

```
core/bible/text/40-마태.md
24:13	그러나 끝까지 인내한 사람은 구원을 받을 것입니다.
24:14	그리고 이 왕국의 좋은 소식이 ...
```

이 형식을 택한 이유는 검색 결과가 자기 설명적이기 때문이다. `"왕국의 좋은 소식"` 을 검색하면 `40-마태.md:24:14` 처럼 어느 절인지가 결과에 그대로 드러난다. 파일을 열지 않고도 위치를 확정할 수 있어 잘못된 인용의 여지가 구조적으로 줄어든다. 파일이 66개뿐이라 관리도 단순하다.

권 번호는 성경 순서(1 창세기 … 66 요한 계시록)를 쓴다. 정렬이 곧 성경 순서가 된다.

## 5. 워크플로

`.claude/skills/` 에 하나씩 둔다. 명령어 이름은 한국어로 한다.

| 명령어 | 하는 일 | 산출물 |
|---|---|---|
| `/집회준비` | 파수대 연구 기사 예습, 생활과 봉사 모임 과제, 주간 성경 읽기 | `activities/meetings/<날짜>/` |
| `/주제연구` | 질문 하나를 코어 + 출판물로 파고들어 정리 | `core/topics/` 생성·갱신 |
| `/공개강연` | 개요를 받아 원고 구성, 성구 배치, 시간 배분 | `activities/talks/` |
| `/봉사준비` | 대화 시나리오, 성구 선택, 예상 반론 대응 | `activities/ministry/` |
| `/통독` | 오늘 분량 읽기 지원, 질문 던지기, 일지 작성 | `activities/reading/` + 진도 갱신 |

### 5.1 공통 데이터 흐름

모든 워크플로가 같은 흐름을 따른다.

```
1. profile/me.md · progress.md 읽기         — 지금 내 상황 파악
2. core/bible/ 에서 본문·연구노트 읽기        — 근거 확보
3. core/topics · verses 에서 기존 정리 찾기   — 중복 연구 방지
4. 부족하면 wol.jw.org 조회                  — URL·날짜 기록
5. activities/... 에 산출물 작성
6. ★ 승격 — 새로 이해한 것을 core 로 올릴지 제안
7. progress.md 갱신
```

6번이 빠지면 이 설계는 의미를 잃는다. 각 워크플로는 반드시 승격 단계로 끝난다.

### 5.2 승격 규칙

활동 중 얻은 것 중에서 다음에 해당하면 코어로 올린다.

- 특정 절에 대한 새로운 이해 → `core/verses/<권>-<장>-<절>.md`
- 여러 성구에 걸친 개념 정리 → `core/topics/<주제>.md`
- 히브리어·그리스어 단어의 의미 → `core/words/<단어>.md`

이미 노트가 있으면 새로 만들지 않고 기존 노트에 덧붙이며, 언제 무엇을 추가했는지 날짜를 남긴다. 노트끼리는 `[[링크]]` 로 연결한다.

## 6. 정확성 규칙

이 도구에서 발생할 수 있는 최악의 실패는 **존재하지 않는 성구를 그럴듯하게 지어내는 것**이다. 프로젝트 `CLAUDE.md` 에 다음을 강제 규칙으로 못 박는다.

1. 성구 인용은 반드시 `core/bible/text/` 에서 실제로 읽은 문자열만 쓴다. 기억에 의존한 인용을 금지한다.
2. 교리적 설명에는 출판물 근거를 단다. 근거를 찾지 못하면 **"출판물 근거 미확인 — 내 정리임"** 이라고 반드시 명시한다.
3. 여호와의 증인의 이해를 기준으로 삼되, 독자적인 새 해석을 만들어내지 않는다.
4. 조회한 출판물은 URL과 조회 날짜를 함께 남긴다.
5. 한국어 문장은 마침표로 끝낸다. 문장 끝에 콜론을 쓰지 않는다.

## 7. 검증

코드가 적은 프로젝트지만 데이터 무결성은 기계로 확인한다. 본문 추출이 조용히 틀리는 것이 가장 위험하다.

### `scripts/verify-bible.mjs`

- 66권이 모두 있는지, 장 수 합계가 1,189인지 확인한다
- 각 권의 장별 절 개수를 **최초 추출 시점의 값으로 `core/bible/index.md` 에 기록**하고, 이후 실행에서 그 값과 대조한다
  - 신세계역은 후대 사본에만 있는 절(마태 17:21 등)을 본문에서 빼고 각주로 처리하므로, 통용되는 31,102절과 총계가 다르다. 따라서 외부 숫자를 기준으로 삼지 않고 최초 추출값을 기준선으로 고정한다
- 빈 절, 장 번호 누락, 절 번호 역행이 없는지 확인한다

### `scripts/verify-links.mjs`

- 노트 안의 `[[링크]]` 가 실제 파일을 가리키는지 확인한다
- 깨진 링크를 목록으로 보고한다. 실패로 처리하되 삭제하지는 않는다

`npm test` 로 두 스크립트를 실행한다.

## 8. 진행 순서

| 단계 | 내용 | 이 순서인 이유 |
|---|---|---|
| **0** | jwpub 복호화 스파이크 | 실패하면 설계가 통째로 바뀐다. 가장 먼저 확인한다 |
| **1** | 골조 + 본문·연구노트·상호참조 추출 + 검증 | 나머지 전부의 토대 |
| **2** | `/집회준비` | 매주 사용하므로 체감 가치가 가장 크다 |
| **3** | `/주제연구` + 성구·주제 노트 체계 | 승격 구조가 여기서 완성된다 |
| **4** | `/통독` · `/봉사준비` · `/공개강연` | 토대가 안정된 뒤에 붙인다 |

각 단계는 독립적으로 사용 가능한 상태로 끝난다. 1단계만 끝나도 성경 전문 검색 도구로서 값어치를 한다.

## 9. 위험 요소와 대비책

| 위험 | 영향 | 대비책 |
|---|---|---|
| jwpub 복호화 실패 | 1단계 전면 재설계 | wol.jw.org에서 본문만 수집한다. 연구 노트와 상호 참조는 포기한다 |
| wol.jw.org 구조 변경 | 출판물 조회 불가 | 해당 주 자료를 직접 붙여넣는 경로를 워크플로에 항상 열어 둔다 |
| 노트가 쌓이며 탐색 곤란 | 축적의 이점 상실 | `core/topics/` 에 색인 노트를 두고, 3단계에서 노트 수가 임계에 이르면 점검한다 |
| 추출 오류를 눈치채지 못함 | 잘못된 성구 인용 | 7절의 기준선 대조 검증을 `npm test` 로 상시 실행한다 |

## 10. 명시적으로 하지 않는 것

- 웹 UI, 모바일 앱, 서버를 만들지 않는다
- 삽화 702개는 1단계에서 추출하지 않는다. 필요해지면 그때 다룬다
- 다른 번역본과의 대조 기능은 넣지 않는다
- 출판물 전체를 로컬에 복제하지 않는다. 필요할 때 조회한다
