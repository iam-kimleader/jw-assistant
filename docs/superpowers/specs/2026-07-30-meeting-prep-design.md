# 2단계 설계 — `/집회준비` (파수대 연구)

- **작성일** 2026-07-30
- **사용자** 김동언 (35세, 여호와의 증인, 광주양림회중)
- **상태** 승인됨
- **상위 설계** `docs/superpowers/specs/2026-07-29-jw-assistant-design.md`

---

## 1. 목적과 범위

주말 집회의 파수대 연구 기사를 예습하는 일을 돕는다. 그 주 기사가 인용한 성구를
1단계에서 구축한 코어 본문으로 전부 펼쳐 주고, 문단 질문과 함께 배치해 형제님이
답을 적을 자리를 만든다.

이번 단계에서 다루지 않는 것을 먼저 못 박는다.

- 우리의 그리스도인 생활과 봉사 모임 과제
- 주간 성경 읽기
- 연구 노트와 각주 (3단계)

파수대가 몇 주 잘 돌아가는 것을 확인한 뒤 같은 틀로 붙인다.

## 2. 결정과 그 이유

### 2.1 기사 본문은 저장하지 않는다

예습지에는 질문, 문단 번호, 인용 성구 본문만 담고 기사 문단은 wol 링크로만 남긴다.
상위 설계 §10 "출판물 전체를 로컬에 복제하지 않는다" 를 지키기 위해서다. 기사는
종이책이나 JW Library 로 읽는다는 전제다.

이 결정은 도구의 값어치를 깎지 않는다. 오히려 코어가 유일하게 줄 수 있는 것 —
검증된 성구 본문과 양방향 난외 참조 — 에 집중하게 만든다. 기사 본문은 어차피
형제님이 다른 경로로 이미 갖고 있다.

### 2.2 스크립트가 예습지를 통째로 만든다

Claude 가 예습지를 구성하지 않는다. `scripts/prepare-meeting.mjs` 가 wol 에서 받아
파싱하고, 코어에서 성구 본문을 넣어 마크다운을 완성한다.

이유는 정확성이다. 예습지의 모든 글자가 wol 원문이 아니면 `core/bible/text/` 에서
온 것이므로, 기억에 의존한 인용이 섞일 자리가 구조적으로 없다. Claude 는 완성된
예습지를 **읽고** 형제님과 대화하며, 마지막에 승급을 제안하는 역할만 맡는다.

### 2.3 라벨 해석 실패는 보이게 남긴다

성구 라벨을 해소하지 못하면 그 자리에 `⚠ 해석 실패` 와 wol 링크를 남기고, 스크립트는
마지막에 "인용 39건 중 37건 해석, 2건 미해결" 을 출력한다.

전체 중단은 택하지 않았다. wol 이 새 표기를 하나 쓰면 그 주 예습을 통째로 못 하게
된다. 조용한 건너뜀도 택하지 않았다. 빠졌다는 사실을 모른 채 지나가는 것이 이
프로젝트가 가장 경계하는 실패다.

## 3. wol 구조 — 실측 결과

2026년 7월 27일–8월 2일 주간 기사(docId 2026403)를 실제로 받아 확인했다.

### 3.1 주간 집회 페이지에서 docId 를 얻는다

`https://wol.jw.org/ko/wol/meetings/r8/lp-ko/{연도}/{ISO주}` 가 그 주 집회 페이지다.
안에 두 항목이 있고 CSS 클래스로 구별된다.

```
todayItem ... docId-202026244 pub-mwb26   ← 생활과 봉사 교재 (이번 단계 대상 아님)
todayItem ... docId-2026403   pub-w26     ← 파수대 연구 기사
```

기사 URL 은 `https://wol.jw.org/ko/wol/d/r8/lp-ko/{docId}` 다.

### 3.2 기사 HTML 구조

| 요소 | 선택자 | 담는 것 |
|---|---|---|
| 주 라벨 | `p.contextTtl` | "2026년 7월 27일–8월 2일" |
| 노래 | `p.pubRefs` 첫 항목 | "노래 56 진리를 자신의 것으로 만들라" |
| 제목 | `h1` | 기사 제목 |
| 주제 성구 | `p.themeScrp` | 인용문 + 성구 링크 |
| 요점 | `p.pubRefs` (요점 상자) | 기사 개요 |
| 질문 | `p.qu` | `<strong>1-2.</strong>` 로 시작, 담당 문단 범위를 품는다 |
| 문단 | `p[data-rel-pid]` | `data-rel-pid="[46]"` 로 자기 질문을 가리킨다 |
| 문단 번호 | `span.parNum[data-pnum]` | 1, 2, 3 … |
| 성구 링크 | `a.b[data-bid]` | 링크 본문이 곧 성구 라벨 |

### 3.3 성구 라벨의 실제 형태

같은 기사 한 편에서 39건이 나왔고 고유 라벨은 34종이다. 다음 여섯 가지를 모두
처리해야 한다.

1. **약칭이 인덱스와 다르다** — `빌립보 3:16`(빌립보서), `계시록 2:4`(요한 계시록),
   `시 133:1`(시편), `전도 4:6`(전도서), `마태 22:37`(마태복음),
   `히브리 10:25`(히브리서), `에베소 6:11-13`(에베소서), `야고보 4:8`(야고보서),
   `골로새 2:8`(골로새서). 같은 기사 안에서 `빌립보 3:16` 과 `빌립보서 3:16` 이
   섞여 나온다.
2. **부분 절 접미사** — `야고보 4:8ㄱ` 의 `ㄱ`. `ㄴ` 도 쓰인다.
3. **목록형** — `마태 28:19, 20`, `잠언 5:1, 2`, `시 101:6, 7`
4. **범위** — `고린도 전서 3:18-20`, `디모데 후서 2:16-18`
5. **후행 세미콜론** — `여호수아 1:8;` 처럼 구분자가 링크 안에 딸려 온다.
6. **권 이름 생략** — `시 101:6, 7; 119:63` 의 `119:63`,
   `고린도 전서 9:26, 27; 10:31` 의 `10:31`

### 3.4 `data-bid` 가 생략된 권 이름을 확정해 준다

6번이 이 단계에서 가장 조용히 틀릴 수 있는 자리였다. 다행히 `data-bid` 가
`{그룹}-{그룹내순번}` 형식이고, 같은 괄호 안의 참조가 같은 그룹 번호를 갖는다.

```
23-1  시 101:6, 7;
23-2  119:63              ← 23-1 에서 시편을 이어받는다
25-1  에베소 6:11-13;
25-2  고린도 전서 9:26, 27;
25-3  10:31               ← 25-2 에서 고린도 전서를 이어받는다
```

따라서 권 이름 이어받기는 **같은 bid 그룹 안에서 직전 참조로부터만** 한다. 그룹이
바뀌면 이어받지 않고, 권 이름 없는 라벨이 그룹의 첫 항목이면 해석 실패로 처리한다.

## 4. 구조

### 4.1 명령어

```bash
npm run 집회준비                 # 오늘이 속한 주
npm run 집회준비 -- 2026-08-02   # 날짜로 다른 주 지정
npm run 집회준비 -- --docid 2026403   # wol 구조가 바뀌었을 때의 우회로
```

산출물은 `activities/meetings/{주 시작일}/파수대-예습.md` 다. 주 시작일은 그 주
월요일을 쓴다. 2026년 7월 27일–8월 2일 주간이면 `activities/meetings/2026-07-27/` 이다.

### 4.2 데이터 흐름

```
날짜 → ISO 주 → wol 주간 집회 페이지 → 파수대 docId
     → 기사 HTML (.cache/wol/ 에 캐시)
     → 질문·문단번호·인용 라벨 파싱
     → 라벨을 core/bible/index.json 으로 해소
     → core/bible/text/ 본문 + core/bible/refs/ 역참조
     → 예습지 .md 쓰기 + 요약 출력
```

### 4.3 모듈

기존 `src/verse-address.mjs` · `src/bible-text.mjs` · `src/refs-lookup.mjs` ·
`src/text-lines.mjs` 를 그대로 쓴다. 새로 넷을 만든다.

| 파일 | 하는 일 | 의존 | 순수성 |
|---|---|---|---|
| `src/wol-week.mjs` | 날짜 → 주간 페이지 → `{주라벨, docId, 기사URL}` | fetch | 네트워크 |
| `src/wol-article.mjs` | 기사 HTML → 구조체 | 없음 | 순수 |
| `src/citation-parse.mjs` | 라벨 → 성구 주소 목록 | verse-address | 순수 |
| `src/prep-sheet.mjs` | 구조체 + 코어 → 마크다운 문자열 | bible-text, refs-lookup | 순수 |
| `scripts/prepare-meeting.mjs` | 조립, 파일 쓰기, 요약 출력 | 위 전부 | 조립 |

네트워크를 타는 것은 `wol-week.mjs` 와 조립 스크립트뿐이고 나머지 셋은 순수 함수라
네트워크 없이 시험할 수 있다. `wol-chapter.mjs` 가 이미 같은 모양을 하고 있으니
그 방식을 따른다.

### 4.4 `wol-article.mjs` 가 내놓는 구조체

```js
{
  주라벨: '2026년 7월 27일–8월 2일',
  제목: '추가 교육을 받는 동안 여호와와 계속 가까운 관계를 유지하십시오',
  노래: '노래 56 진리를 자신의 것으로 만들라',
  주제성구: { 인용문: '우리가 어느 정도까지…', 라벨: '빌립보 3:16', bid: '1-1' },
  요점: '추가 교육을 받는 동안 어떻게 영적으로 강한 상태를 유지할 수 있습니까? …',
  문단그룹: [
    {
      질문: '(ㄱ) 추가 교육을 받기로 결정한다면 계속 어떻게 할 필요가 있습니까? …',
      문단번호: [1, 2],
      인용: [
        { 라벨: '빌립보서 3:16', bid: '28-1', 낭독: false },
        { 라벨: '야고보 4:8ㄱ',  bid: '2-1',  낭독: false },
        { 라벨: '빌립보서 3:16', bid: '3-1',  낭독: true  }
      ]
    }
  ]
}
```

`낭독` 은 링크 뒤에 `<strong>낭독.</strong>` 이 붙은 경우다. 집회에서 소리 내어 읽는
성구이므로 예습지에서 눈에 띄게 표시한다.

### 4.5 `citation-parse.mjs` 의 계약

```js
parseCitation(index, 라벨, 직전권)
// → { 성공: true,  주소들: [{book, chapter, verse, verseId}], 권 }
// → { 성공: false, 사유: '권을 찾을 수 없다: 요한' }
```

예외를 던지지 않고 실패를 값으로 돌려준다. 호출자가 39건을 돌면서 실패 하나에
멈추지 않게 하기 위해서다. `직전권` 은 같은 bid 그룹의 직전 참조가 해소한 권이며,
그룹의 첫 항목이면 `null` 이다.

권 이름 해소는 세 단계를 이 순서로 밟는다. 하나라도 모호하면 실패로 본다.

1. 공백을 무시한 완전 일치 — `고린도 전서`, `여호수아`
2. 예외표 — `계시록` → 요한 계시록
3. 접두 유일 일치 — `빌립보` → 빌립보서. 후보가 둘 이상이면 실패다
   (`요한` 은 요한복음·요한 1서·요한 2서·요한 3서·요한 계시록 다섯 후보라 실패)

예외표는 손으로 66개를 채우지 않고, 3단계 규칙으로 풀리지 않는 것만 넣는다. 새
약칭이 나타나면 미해결로 드러나므로 그때 한 줄 추가한다.

때문이다. 궁금한 것은 `성구` 명령으로 따로 본다.

### 4.7 `/집회준비` 스킬

`.claude/skills/집회준비/SKILL.md` 가 하는 일은 넷이다.

1. `npm run 집회준비` 실행
2. 생성된 예습지를 읽는다
3. 형제님과 대화한다 — 질문에 답을 잡고, 막히는 문단을 함께 본다
4. 상위 설계 §5.2 에 따라 승급을 제안한다. 특정 절의 새 이해는 `core/verses/`,
   여러 성구에 걸친 개념은 `core/topics/`, 원어는 `core/words/` 다

스킬은 성구 본문을 직접 옮겨 적지 않는다. 필요하면 `src/bible-text.mjs` 를 import
한다. `성구.cmd` 는 부르지 않는다 — 파일 이름이 한국어라 프로그램이 부르면 깨진다.

## 5. 정확성 장치

상위 설계 §6 의 규칙이 이 단계에서 어떻게 지켜지는지 적는다.

| 규칙 | 이 단계에서의 이행 |
|---|---|
| 1. 성구는 코어에서 읽은 것만 | 예습지의 성구 본문 전량이 `core/bible/text/` 에서 온다. 스크립트가 넣으므로 예외가 불가능하다 |
| 2. 교리 설명에는 근거 | 스크립트는 교리 설명을 하지 않는다. 대화 중 Claude 가 설명하면 근거를 달거나 "출판물 근거 미확인" 을 명시한다 |
| 3. 새 해석을 만들지 않음 | 예습지는 기사의 질문을 그대로 옮기고 답을 비워 둔다 |
| 4. URL 과 조회 날짜 | 예습지 말미의 출처 절에 남긴다 |
| 5. 마침표로 끝냄 | 스크립트가 만드는 고정 문구에 적용한다. 기사에서 옮긴 질문은 원문 그대로 둔다 |

## 6. 시험

TDD 로 간다. 순수 모듈 셋이 시험의 대부분을 진다.

### 6.1 픽스처

실제 기사 HTML 을 저장소에 넣으면 §2.1 에서 정한 원칙과 어긋난다. 그래서 **구조는
실물을 본뜨되 문단 본문 자리는 더미 텍스트로 채운 합성 픽스처**를 만든다.
`tests/fixtures/파수대-기사-합성.html` 이다.

성구 라벨 34종은 실제로 나온 것을 그대로 넣는다. 라벨은 성구 주소일 뿐 출판물
본문이 아니다. 이러면 시험이 네트워크 없이 돌고 매번 같은 결과를 낸다.

### 6.2 시험 항목

**`citation-parse.test.mjs`**

- §3.3 의 라벨 34종이 전부 옳은 절 ID 로 풀리는지
- `야고보 4:8ㄱ` 이 `야고보서 4:8` 로 풀리고 접미사가 버려지는지
- `마태 28:19, 20` 이 두 주소로 풀리는지
- `고린도 전서 3:18-20` 이 세 주소로 풀리는지
- `여호수아 1:8;` 의 후행 세미콜론이 무시되는지
- `119:63` 이 직전 권 시편을 이어받는지
- `10:31` 이 직전 권 고린도 전서를 이어받는지
- 권 없는 라벨이 그룹 첫 항목이면 실패로 떨어지는지
- `요한` 이 모호함으로 실패하는지 — 조용히 아무거나 고르지 않는다
- 없는 절(`창세기 1:99`)이 실패로 떨어지는지

**`wol-article.test.mjs`**

- 합성 픽스처에서 제목·주 라벨·노래·주제 성구·요점이 뽑히는지
- 문단그룹이 `data-rel-pid` 로 옳게 묶이는지
- 문단 번호가 `data-pnum` 에서 뽑히는지
- `낭독` 표시가 잡히는지
- bid 그룹 순서가 문서 순서대로 보존되는지

**`prep-sheet.test.mjs`**

- 성구 본문이 코어에서 온 문자열과 정확히 같은지
- 실패한 인용이 `⚠` 로 남고 미해결 절에 모이는지
- 출처 절에 URL 과 조회 날짜가 들어가는지

**`wol-week.test.mjs`**

- 날짜 → ISO 주 변환이 연말·연초 경계에서 맞는지 (네트워크 불필요)
- 저장된 주간 페이지 조각에서 `pub-w` 항목의 docId 를 고르는지

### 6.3 회귀 기준

이번 기사에서 인용 39건 중 몇 건이 해석되는지를 숫자로 못 박는다. 목표는 39건
전부다. 구현 후 실제 값을 이 문서와 `checklist.md` 에 적고, 이후 이 숫자가 떨어지면
회귀로 본다.

## 7. 실패 대비

| 위험 | 대비책 |
|---|---|
| wol 주간 페이지 구조 변경 | `--docid` 로 기사를 직접 지정하는 우회로를 둔다 |
| 기사 HTML 구조 변경 | 파싱 결과가 비면 예습지를 쓰지 않고 무엇이 비었는지 보고한다 |
| 새 성구 약칭 등장 | 미해결로 드러난다. 예외표에 한 줄 추가한다 |
| 네트워크 실패 | `.cache/wol/` 캐시를 먼저 본다. 1단계 `fetch-bible.mjs` 와 같은 방식이다 |

## 8. 완료 기준

- `npm test` 가 통과한다
- `npm run 집회준비` 가 이번 주 예습지를 만든다
- 예습지의 성구 본문이 `성구` 명령의 출력과 글자 단위로 같다
- 인용 39건 중 39건이 해석된다
- 형제님이 예습지를 실제로 보고 쓸 만하다고 확인한다
