# 자료 보관과 마이페이지 설계

/ 2026-08-27 · 김동언 형제와 브레인스토밍하여 정함

앞선 설계 `2026-08-26-kakao-login-storage-design.md` 의 3~4단계를 이어받는다.
로그인은 2026-08-27 에 배포되어 실제로 돌아가고 있다.

## 1. 무엇을 푸는가

지금은 화면을 나갔다 돌아오면 만든 자료가 사라진다. 다시 만들려면 OpenAI 를
또 부르고 돈이 또 든다. 회중의 여러 분이 같은 주간을 각자 열면 같은 답변을
사람 수만큼 만든다.

두 가지를 고친다.

- **만든 것을 서버에 남긴다.** 돌아오면 그대로 있다
- **주간 답변을 회중이 나눠 쓴다.** 한 번 만들면 모두가 본다

## 2. 왜 두 차례로 나누는가

1차는 저장이고 2차는 마이페이지 화면이다. 순서를 뒤집을 수 없다. **저장이
안 되면 보관함에 보여 줄 것이 없다.**

그리고 토큰 낭비라는 문제 자체는 1차에서 끝난다. 마이페이지는 쌓인 것을 편하게
꺼내 보는 창구지 문제를 푸는 부분이 아니다. 1차를 배포해 실제로 쓰면서 보관함에
무엇이 있어야 편한지 확인한 뒤 2차를 설계한다. 지금 상상해서 화면을 짜는 것보다
낫다고 보았다.

이 문서는 1차를 정하고, 2차에서 만들 것을 11절에 기록만 해 둔다.

## 3. 저장 구조

```
weeks/watchtower/{주간}.json          공용
weeks/life-ministry/{주간}.json       공용
users/{회원번호}/profile.json         닉네임·처음온때 + 화자 설정 일곱
users/{회원번호}/talks/{주간}-{배정번호}.json
```

Vercel Blob 비공개 저장소를 쓴다. 읽기에도 인증이 필요하고 함수를 거쳐서만
나간다. 앞 설계에서 이미 만들어 붙였다.

### 주간 답변이 공용인 이유

`prepareWatchtower(날짜)` 와 `prepareLifeAndMinistry(날짜)` 는 날짜만 받는다.
사람에 따라 달라지지 않는다. 그래서 한 번 만들어 공용으로 두는 것이 맞다.
회중 다섯 분이 같은 주를 열면 지금은 다섯 번 만들지만 앞으로는 한 번이다.

### 주간 열쇠는 서버가 정규화한다

화면이 보낸 날짜를 그대로 열쇠로 쓰면 안 된다. 같은 주인데 날짜가 하루 다른
요청이 오면 별개로 저장되어 캐시가 조용히 새고 같은 내용이 두 벌 생긴다.

서버가 **주간 시작일로 정규화한 뒤** 열쇠로 쓴다. 정규화되지 않는 날짜는
거부한다.

### 설정을 `profile.json` 에 합치는 이유

지금 그 파일에는 닉네임과 처음 온 때가 들어 있다. 거기에 화자 프로필 일곱을
더한다. 성별, 연령, 임명, 파이오니아 여부, 스타일, 문체 견본, 분당 글자 수다.

파일을 나누지 않는 이유가 있다. **`GET /api/options` 는 화면이 뜰 때 이미
부른다.** 거기에 설정을 실어 보내면 읽기용 엔드포인트를 새로 만들 필요가 없다.
로그인 작업에서 `사용자` 를 실은 것과 같은 방식이다. 저장할 때만 새 엔드포인트가
하나 필요하다.

로그인이 이 파일을 쓰는 것은 **없을 때 한 번뿐**이라, 나중에 설정을 저장해도
덮어쓰지 않는다.

### 설정을 서버로 옮기는 이유

지금은 브라우저의 localStorage 에 있다. 그래서 폰과 컴퓨터가 따로 논다. 서버로
옮기면 어디서 들어와도 따라온다. 임명 값이 기기마다 다르면 공개강연이 배정
목록에서 보였다 안 보였다 하므로, 일곱 중 일부만 옮기지 않고 전부 옮긴다.

### 연설 자료는 주간과 배정으로 한 칸이다

같은 주 같은 배정을 다시 만들면 덮어쓴다. 여러 벌을 남기지 않는다. 필요한 것은
지난 것을 다시 보는 일이지 여러 판을 비교하는 일이 아니다.

**배정번호는 그 주간 배정 목록에서의 순번이다.** 종류를 열쇠로 쓸 수 없다. 한
주에 학생연설이 여럿 있어 종류만으로는 서로 구별되지 않는다. 순번은 같은 교재
페이지를 파싱한 결과라 같은 주간 안에서는 고정이다.

다만 이 열쇠는 **주간 안에서만 뜻이 있다.** 교재 페이지가 나중에 고쳐져 순서가
바뀌면 저장된 자료가 다른 배정에 붙어 보일 수 있다. 그래서 저장할 때 배정의
제목도 함께 넣고, 복원한 뒤 지금 배정의 제목과 다르면 **복원하지 않고 없는 것으로
본다.** 잘못된 원고를 맞는 것처럼 보여 주는 쪽이 다시 만드는 것보다 나쁘다.

### 판 번호

모든 파일에 `"판": 1` 이 붙는다. 모양이 바뀌면 판을 올리고, 판이 다른 파일은
**없는 것으로 본다.** 옛 자료를 새 모양으로 옮기는 작업은 하지 않는다. 전부 다시
만들 수 있는 것들이라 이관 코드를 쓰고 검증하는 값이 나오지 않는다.

## 4. 화면 동작

### 생활과 봉사·파수대

```
"준비" 를 누른다
  → 저장된 것이 있나?
      있으면 → 즉시 표시. 진행률 게이지 없음. 토큰 0
      없으면 → 만든다 → 저장한다 → 표시
```

저장된 것을 보여 줄 때 위에 띠가 붙는다.

```
┌──────────────────────────────────────────────┐
│ 2026-08-26 에 만들어진 답변입니다.  [다시 만들기] │
└──────────────────────────────────────────────┘
```

다시 만들기는 확인을 거친다.

> 이번 주 답변이 이미 있습니다. 다시 만들면 이전 답변은 사라지고, 회중의 다른
> 분들께도 새 답변이 보이게 됩니다. 계속할까요?

공용본이 하나뿐이라 다시 만들면 남의 것도 같이 바뀐다. 회중 몇 분이 서로 아는
사이이므로 확인 문구로 충분하다고 보았다. 문구에 "다른 분들께도" 를 넣은 이유가
이것이다.

확인 대화는 `window.confirm` 이 아니라 shadcn `AlertDialog` 로 만든다. 브라우저
기본 대화상자는 화면 자동 검증 도구를 멈춰 세워 그 뒤로 아무것도 확인할 수 없게
만든다.

### 연설

배정을 고르면 저장된 것이 있는지 먼저 본다. 있으면 뼈대와 산출물이 복원되어
뼈대 만들기부터 다시 할 필요가 없다. 화면을 나갔다 돌아와도 그대로다.

뼈대가 만들어지면 그 자리에서 저장하고, 원고가 만들어지면 다시 저장한다.
**뼈대만 만들고 나가도 날아가지 않는다.** 뼈대도 OpenAI 호출이라 돈이 든다.

### 설정

연설 화면의 화자 프로필은 지금 자리에 그대로 둔다. 다만 저장처가 브라우저에서
서버로 바뀐다. 값을 고치면 서버에 저장된다.

## 5. API

### 기존 여섯 — 파일은 그대로, 속만 바뀐다

| 엔드포인트 | 무엇이 달라지나 |
|---|---|
| `GET /api/options` | 응답에 `설정` 을 싣는다 |
| `GET /api/watchtower?date=` | 저장된 것을 먼저 본다 |
| `GET /api/life-ministry?date=` | 저장된 것을 먼저 본다 |
| `GET /api/talk-assignments` | 그대로 |
| `POST /api/talk-outline` | 만든 뒤 저장한다. 요청에 `주간` 이 는다 |
| `POST /api/talk-draft` | 만든 뒤 저장한다. 요청에 `주간` 이 는다 |

### 새로 넷

| 엔드포인트 | 무엇을 |
|---|---|
| `POST /api/watchtower` | 다시 만들기 |
| `POST /api/life-ministry` | 다시 만들기 |
| `GET /api/my-talk?주간=&배정번호=` | 저장된 연설 자료 하나 복원 |
| `POST /api/my-profile` | 설정 저장 |

다시 만들기는 파일을 새로 만들지 않고 기존 `api/watchtower.js` 안에서 메서드로
가른다. Vercel 이 경로로 파일을 찾으므로 한 파일이 GET 과 POST 를 같이 받으면
된다. `vercel.json` 의 `functions` 글롭이 `api/*.js` 라 중첩 폴더를 잡지 못하는
제약과도 맞는다.

**다시 만들기를 POST 로 분리한 이유가 있다.** GET 에 `force=1` 을 붙이면 브라우저
새로고침이나 미리 가져오기만으로도 의도치 않게 돈 드는 호출이 나갈 수 있다. 돈
드는 동작을 GET 에 두지 않는다.

**연설 저장에는 주간이 필요하다.** 지금 `POST /api/talk-outline` 은 배정과
프로필만 받아서 어느 주의 것인지 모른다. 저장할 칸을 정할 수 없으므로 요청에
주간을 하나 더 싣는다. 화면은 이미 알고 있는 값이다.

### 경로가 될 값은 브라우저에서 받지 않는다

앞 설계는 `GET /api/my-talk?key=파일이름` 으로 두고 `key` 에 `/` 나 `..` 가 있으면
거부하기로 했다. 막을 수는 있으나 **브라우저가 보낸 글자가 파일 경로의 일부가
되는 구조 자체가 남는다.** 걸러야 할 글자를 하나라도 빠뜨리면 남의 폴더가 열린다.

대신 화면은 **주간(날짜)과 배정 번호(정수)** 를 보내고 **파일 이름은 서버가
만든다.** 날짜는 주간 목록에 있는 값인지 확인하고, 배정 번호는 정수인지 확인한다.
둘 다 모양이 정해진 값이라 경로가 될 수 있는 글자가 아예 들어오지 못한다. 거르는
것보다 못 들어오게 하는 편이 확실하다.

## 6. 코드 구조

### 캐시 판단을 서비스 함수 하나로 모은다

"저장된 게 있나 → 없으면 만들고 저장" 은 다섯 자리에 필요하다. 파수대와 생활과
봉사 각각, 그리고 Vercel 과 로컬 서버 두 곳씩이다. **어댑터마다 베껴 넣으면 네
벌이 되어 한쪽만 고치는 사고가 나기 쉽다.**

```
주간자료가져오기({ 종류, 날짜, 저장소, 만들기, 다시만들기 })
  → { 자료, 만든때, 새로만듦 }
```

어댑터는 지금처럼 다섯 줄짜리로 남는다. 로그인 작업과 같은 방식으로 바깥
(저장소·OpenAI)을 주입해 시험에서 갈아 끼운다.

### 경로 만들기를 따로 뺀다

```
src/storage-paths.mjs
  주간열쇠(날짜)                     주간 시작일로 정규화. 아니면 던진다
  주간경로(종류, 주간)
  연설경로(회원번호, 주간, 배정번호)   정수가 아니면 던진다
  설정경로(회원번호)
```

순수 함수라 `node --test` 로 전부 덮인다.

### 두 surface 를 발맞춘다

`api/*.js` 와 `src/web-server.mjs` 는 같은 서비스 함수를 부른다. 한쪽에만 들어간
변경은 결함이다. 로그인 작업의 모든 검토가 이 성질을 확인했고, 이번에도 같다.

## 7. 오류 처리

| 무슨 일 | 어떻게 |
|---|---|
| 세션 없음 | 401. 화면이 `/login` 으로 보낸다 (이미 있음) |
| 저장소 읽기 실패 | 없는 것으로 보고 새로 만든다 |
| 판 번호가 다름 | 없는 것으로 보고 새로 만든다 |
| **저장소 쓰기 실패** | **조용히 넘기고 만든 것은 그대로 보여 준다** |
| 날짜가 정규화 안 됨 | 400 |
| 배정 번호가 정수 아님 | 400 |
| 저장된 배정 제목이 지금과 다름 | 없는 것으로 보고 새로 만든다 |
| 설정 저장 실패 | 화면에 알린다. 값은 이번 방문 동안 메모리에 남는다 |

**쓰기 실패로 화면을 막지 않는 것이 중요하다.** OpenAI 호출은 이미 끝나서 돈이
나간 뒤다. 여기서 오류를 띄우면 값을 치르고 아무것도 받지 못한다. 만들어진 것은
무조건 보여 주고 저장 실패는 삼킨다. 다음에 열면 없을 뿐이다.

앞 설계 7절이 "신원을 정하는 읽기에는 삼키기를 적용하지 않는다" 고 정했다. 여기
읽기는 신원을 정하지 않고 자료를 찾을 뿐이므로 삼켜도 된다.

### 동시 생성

같은 주를 두 사람이 동시에 열면 둘 다 저장된 게 없다고 보고 각자 만들어 나중
것이 남는다. OpenAI 호출이 한 번 더 나가는 낭비다. 막으려면 순서를 조율하는
장치가 필요한데 지금 구조에 없다. **몇 초짜리 창이고 손해가 호출 한 번이라 그냥
둔다.**

## 8. 시험

`node --test` 로 덮는 것은 이렇다.

- 경로 만들기 — 남의 폴더를 노리는 입력을 거부하는가
- 주간 열쇠 — 같은 주의 다른 날짜가 같은 열쇠로 모이는가
- 캐시 판단 — 있으면 안 만들고, 없으면 만들고 저장하는가
- 다시 만들기 — 저장된 게 있어도 새로 만드는가
- 판 번호 — 다르면 없는 것으로 보는가
- 쓰기 실패 — 화면을 막지 않고 만든 것을 돌려주는가
- 배정 제목이 달라진 자료 — 복원하지 않고 없는 것으로 보는가

앞의 둘이 특히 중요하다. **조용히 틀리는 종류라 눈으로 볼 수 없다.**

카카오와 Blob 은 시험에서 실제로 부르지 않는다. 주입해서 갈아 끼운다.

### 덮이지 않는 것

**화면이다.** 이 저장소에는 React 시험 장치가 없고, 이 환경에서는 브라우저 도구가
로컬에 붙지 못한다. 서버에서 한 번 그려 보는 것(`npm run smoke:web`)까지만
자동으로 확인하고, 실제로 보기 좋은지는 형제가 본다.

로그인 작업 때 타입 검사·시험·서버 렌더가 모두 통과한 상태에서 연설 화면의 주간
선택 칸이 화면 밖으로 나가 있었다. 브라우저가 배치를 계산해야만 드러나는
종류다. 이번에도 같은 방식으로 나눈다.

## 9. 아직 확인되지 않은 것

- **Blob 비공개 저장소의 실제 읽기 속도.** 매 요청마다 읽으므로 느리면 체감된다.
  1차 배포 뒤 재어 보고 필요하면 함수 인스턴스 안에서 짧게 캐시한다
- **주간 시작일 정규화가 `buildWeekOptions()` 가 주는 값과 맞는지.** 구현 계획에서
  실제 값을 확인한 뒤 정한다
- **한 주간 답변의 크기.** Blob 한 파일로 다루기에 큰지 재어 본다

## 10. 단계

1. **경로와 캐시 판단** — 순수 모듈과 시험
2. **주간 답변 저장·복원·다시 만들기** — 두 surface
3. **설정 서버 이전** — `/api/options` 에 싣고 저장 엔드포인트를 만든다
4. **연설 자료 저장·복원** — 두 surface
5. **배포하고 실제로 확인**

여기까지가 1차다.

## 11. 2차에서 만들 것

브레인스토밍에서 정해 두었다. 1차를 써 본 뒤 별도 문서로 설계한다.

- **들어가는 곳** — 상단 막대의 닉네임을 누르면 마이페이지로 간다. 상단 항목을
  늘리지 않는다. 매일 쓰는 넷을 앞에 두고 가끔 쓰는 것을 뒤로 보낸다. 휴대폰에서
  상단이 줄바꿈되지 않는다
- **보관함의 연구 답변** — 저장된 주간 전부를 날짜 순으로 보인다. 누가 만들었는지
  기록하지 않기로 했으므로 "내가 만든 것" 을 가려낼 수 없다. 보이는 것과 실제가
  같은 쪽을 골랐다
- **보관함의 연설 자료** — 내 것만 보인다. 보기·지우기·내려받기를 한다. 지울 때
  확인을 한 번 묻는다
- **설정** — 화자 프로필 일곱을 마이페이지에서도 고칠 수 있게 한다

## 12. 하지 않는 것

- 여러 판 보관. 같은 주 같은 배정은 한 칸이고 덮어쓴다
- 옛 판 자료의 이관. 판이 다르면 없는 것으로 보고 다시 만든다
- 동시 생성 잠금. 손해가 호출 한 번이라 값이 안 나온다
- 회원 탈퇴 시 자료 삭제. 카카오 웹훅이 필요하다. 언젠가 해야 하나 이번이 아니다
- 저장 용량 제한이나 오래된 자료 정리. 몇 사람이 쓰는 규모라 아직 문제가 아니다
