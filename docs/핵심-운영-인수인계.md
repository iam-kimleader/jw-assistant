- 이 문서는 현재 서비스의 운영과 후속 개발에서 가장 먼저 읽어야 하는 정본이다.
- 결정 과정과 과거 장애의 상세 기록은 `context-notes.md`에 보존되어 있다.

- 현재 운영 배포는 `dpl_D5mHjGdWm9W6R4nzGbDDbpf6B5m3`이며 `READY` 상태다.
- Vercel 런타임은 Node 24.x이며 `OPENAI_API_KEY`는 값이 숨겨진 Sensitive 변수로 Preview와 Production에 등록되어 있다.

## 2. 절대 지켜야 할 정확성 원칙

1. 성구 인용은 반드시 `core/bible/text/`에서 실제로 읽은 문자열만 사용한다. 기억이나 모델 지식으로 성구 문장을 만들지 않는다.
2. 교리적 설명은 WOL 출판물 근거를 사용한다. 근거가 없으면 `출판물 근거 미확인 — 내 정리임.`이라고 표시한다.
3. 여호와의 증인의 이해를 기준으로 삼고 독자적인 새 교리를 만들지 않는다.
4. 출판물은 공식 WOL URL과 조회 날짜를 함께 보존한다.
5. AI 답변은 연구 보조 초안이다. 공식 출판물이나 성경 본문을 대체하는 권위 있는 답변으로 취급하지 않는다.
6. 출판물 본문은 서버에서 AI 근거로만 사용한다. 브라우저 API 응답에서는 본문을 제거하고 제목, 출판물명, URL, 조회일만 공개한다.
7. `OPENAI_API_KEY`는 서버 환경 변수로만 둔다. 브라우저 코드, 로그, Git에는 절대 넣지 않는다.

## 3. 현재 데이터 흐름

1. 브라우저가 선택한 날짜를 `/api/life-ministry` 또는 `/api/watchtower`에 보낸다.
2. 서버가 WOL 주간 페이지에서 해당 교재와 연구 기사를 찾는다.
3. 생활과 봉사는 영적 보물 찾기와 그 주의 회중 성서 연구 서책 및 장을 찾는다.
4. 질문, `(ㄱ)`과 `(ㄴ)` 하위 질문, 소제목, 인용 성구, 삽화를 구조화한다.
5. 성구 본문은 `core/bible/text/`, 상호 참조는 `core/bible/refs/`에서 읽는다.
6. 영적 보물 2는 주간 성경 읽기 장 또는 편 범위 전체를 로컬 성경 코어에서 읽어 전용 AI 근거로 사용한다.
7. 질문에 연결된 WOL 참고 출판물의 정확한 항 범위를 `src/wol-reference-map.json`으로 찾고 실제 `/d/` 문서를 읽는다.
8. OpenAI Responses API가 출판물 문장, 참고 출판물 본문, 성구 본문, 삽화를 근거로 답변을 만든다.
9. 서버가 출판물 본문과 주간 읽기 전체 본문을 제거한 뒤 답변, 선택 성구, 클릭 가능한 공식 링크만 브라우저에 반환한다.
10. 화면은 답변만 복사하며 참고 성구와 출판물 정보는 클립보드에 넣지 않는다.

## 4. 다시 겪으면 안 되는 핵심 장애와 해결법

### Vercel 함수에 성경 코어가 빠지는 문제

Vercel은 `fs`로 읽는 `core/bible/**` 파일을 자동으로 함수 번들에 넣지 못했다. 이 설정을 제거하면 운영 API가 `core/bible/index.json`을 찾지 못한다.

```json
"functions": {
  "api/*.js": {
    "includeFiles": "core/bible/**"
  }
}
```

### Vercel에서 WOL 요청이 불안정한 문제

`src/wol-fetch.mjs`의 IPv4 우선 DNS, `Accept-Encoding: identity`, Node `https` 폴백, 제한 시간과 오류 요약은 운영 안정성을 위해 필요하다. 일반적인 `fetch` 한 줄로 되돌리지 않는다.

WOL의 `/pc/` 참고 링크는 로컬에서는 307 리디렉션을 주지만 Vercel에서는 서울 리전에서도 반복해서 `ETIMEDOUT`이 났다. 반면 실제 기사 `/d/` 경로는 정상 동작했다. 그래서 `/pc/` 링크를 운영 중에 직접 해석하지 않고 로컬에서 정확한 `/d/...#h=` 범위로 미리 해석해 `src/wol-reference-map.json`에 저장한다.

### 참조 매니페스트는 매주 갱신해야 한다

`src/wol-reference-map.json`은 2026-08-08 기준 선택 가능한 21주의 링크 47개를 담는다. 날짜 범위가 매주 이동하므로 아래 명령을 정기적으로 실행하고 변경된 JSON을 커밋한 뒤 배포해야 한다.

```bash
npm run refresh:references
npm test
```

매니페스트에 없는 링크는 짧은 실시간 해석을 시도하지만 Vercel에서는 실패할 가능성이 높다. 이를 정상적인 주 경로로 의존하지 않는다.

### 회중 성서 연구 서책은 완전 자동이 아니다

생활과 봉사 교재에서 서책명과 장을 읽지만 WOL 출판물 심벌은 `src/ministry-meeting.mjs`의 `서책심벌`에 등록되어 있어야 한다. 현재 확인된 값은 `용하 → wcg`, `순 → rr`이다. 회중 성서 연구 서책이 바뀌면 새 약칭과 WOL 심벌을 확인해 이 표에 추가하고 실제 주간 API로 검증해야 한다.

`용하`는 질문에 기존 `class="qu"` 대신 질문 바로 뒤의 `div.gen-field`를 사용한다. `src/wol-article.mjs`의 대화형 서책 폴백을 제거하면 회중 성서 연구 질문이 사라진다.

### OpenAI에 WOL 이미지 URL을 직접 보내면 실패한다

OpenAI가 WOL 원격 이미지 URL을 `400 invalid_value`로 거부했다. `src/ai-answer.mjs`는 서버에서 이미지를 먼저 내려받아 Base64 데이터 URL로 변환한 뒤 입력한다. 이 경로가 삽화 추론의 필수 조건이다.

### 영적 보물 2는 다른 질문의 자료를 사용하면 안 된다

`이번 주 성경 읽기를 통해 어떤 영적 보물을 발견했습니까?`에는 질문 자체의 인용 성구가 없다. 이 질문에 근거를 따로 주지 않으면 같은 AI 요청의 회중 성서 연구 내용이 섞일 수 있다. `src/weekly-reading.mjs`가 교재 날짜 아래의 `성경범위`를 로컬 성경 코어에서 모두 펼쳐 이 질문에만 제공한다.

AI는 제공된 범위 안의 특정 성구 주소를 `selectedVerse`로 반환해야 한다. 서버가 주소를 검증하며 범위 밖 성구이거나 빈 값이면 AI 답변을 채택하지 않는다. API에는 전체 읽기 본문을 내보내지 않고 최종 선택 성구 하나만 표시한다.

### AI 요청은 길고 부분 실패가 가능하다

15개 답변을 한 요청으로 만들면 180초를 넘겼다. 현재 기본 모델은 `gpt-5.4-mini`, 추론 강도는 `low`, 묶음 크기는 5개이며 여러 묶음을 병렬 실행한다. 각 OpenAI 요청 제한 시간은 120초다.

묶음 일부만 실패하면 성공한 AI 답변은 유지하고 실패한 묶음만 공식 자료 기반 초안으로 돌린다. API 키가 없거나 전체 호출이 실패해도 서비스는 폴백 답변을 반환해야 한다.

실제 2026년 8월 3일 주간 생활과 봉사 운영 검증은 약 125.3초가 걸렸고 15개 답변 모두 AI 모드로 생성됐다. 성능 변경 뒤에는 짧은 단위 테스트만으로 끝내지 말고 운영 API를 한 번 실제 호출한다.

### 진행률은 실제 서버 단계가 아니라 예상치다

현재 API는 완료 JSON을 한 번에 반환하므로 브라우저가 실제 세부 단계 진행률을 알 수 없다. 원형 게이지는 운영 시간을 기준으로 3%에서 96%까지 올라가는 예상 진행률이며 응답이 성공한 뒤에만 100%가 된다. 실제 진행률로 표시하거나 100%에서 서버를 기다리게 만들지 않는다.

실제 진행률이 필요해지면 요청을 작업 ID 기반 비동기 작업으로 바꾸고 스트리밍 또는 폴링 상태 API를 추가해야 한다.

## 5. 답변과 화면에서 유지해야 할 동작

- `(ㄱ)`과 `(ㄴ)`은 별도 답변 카드와 별도 `답변 복사` 버튼을 가진다.
- `토의해 보십시오`, `더 깊이 알아보기`, `교훈점 적용하기`, `시야를 넓혀 생각해 보기` 같은 소제목을 보존한다.
- 답변 영역은 연한 초록색이며 참고 성구와 시각적으로 구분한다.
- 별도 참고 자료가 있는 질문은 정확한 기사 항 범위 링크를 표시한다.
- 별도 참고 자료가 없는 질문도 해당 질문이 실린 공식 WOL 원문 링크를 표시한다.
- `답변 복사`는 `answer.답변`만 복사한다.
- AI 답변은 보통 3문장부터 6문장으로 작성하고 원인과 결과, 시간 순서, 대조점, 실생활 의미를 필요한 만큼 연결한다.
- `문단의 흐름을 근거로 보면`, `성구 근거로는` 같은 반복 문구를 다시 넣지 않는다.
- 한국어 이외의 문자 체계가 섞이지 않도록 모델 지침과 출력 정규화를 유지한다.

## 6. 운영 명령과 배포 절차

### 로컬 실행과 검증

```bash
npm test
npm run web
```

기본 로컬 주소는 `http://localhost:3000`이다. 다른 프로세스가 사용 중이면 PowerShell에서 `$env:PORT='3017'`처럼 포트를 바꾼 뒤 실행한다.

AI를 로컬에서 검증할 때는 `.env.example`을 참고하되 키 파일을 커밋하지 않는다. 기본 모델은 환경 변수 `OPENAI_MODEL`, 묶음 크기는 `OPENAI_BATCH_SIZE`로 바꿀 수 있다.

### 참조 링크 갱신

```bash
npm run refresh:references
npm test
```

갱신 뒤 `src/wol-reference-map.json`의 변경 수와 실패 경고를 확인한다. WOL 구조 오류를 단순 네트워크 오류로 간주하고 넘어가지 않는다.

### 운영 배포

```bash
npx vercel --prod --yes
```

배포 뒤 아래 항목을 확인한다.

- `/`가 HTTP 200인지 확인한다.
- `/api/options`가 21주를 반환하는지 확인한다.
- `/progress.js`가 JavaScript로 HTTP 200을 반환하는지 확인한다.
- 생활과 봉사 또는 파수대 API 하나를 실제 호출해 `generation.mode`, 답변 수, 참고 링크 수를 확인한다.
- Vercel 환경 변수 `OPENAI_API_KEY`가 Production에 설정되어 있는지 확인한다.
- 비밀 키나 출판물 본문이 브라우저 API 응답에 포함되지 않았는지 확인한다.

Vercel 계정의 GitHub Login Connection이 없어 자동 배포 연결은 아직 완료되지 않았다. 현재는 로컬 CLI 업로드 방식이다. 자동 배포를 사용하려면 계정 연결을 먼저 설정하고, 그 전까지는 GitHub 푸시와 Vercel 배포를 별도 작업으로 취급한다.

## 7. 남은 위험과 다음 개발 순서

### 가장 높은 위험

- WOL HTML 클래스나 문서 구조가 바뀌면 질문과 참고 항 파서가 조용히 누락할 수 있다. 실제 주간 데이터 테스트를 유지한다.
- 회중 성서 연구 서책이 바뀌면 `서책심벌` 등록이 없어서 자동 조회가 실패한다.
- 참조 매니페스트를 갱신하지 않으면 새 주간의 참고 출판물 본문을 AI가 받지 못할 수 있다.
- AI 답변은 공식 자료를 근거로 해도 생성 결과이므로 사실과 추론이 섞이지 않았는지 표본 검토가 필요하다.

### 운영상 제한

- 준비 시간은 약 2분이며 네트워크와 OpenAI 상태에 따라 달라진다.
- 진행률은 예상치다.
- `package.json`의 Node 버전은 `>=24`여서 미래의 새 메이저 버전으로 자동 상승할 수 있다. 런타임 장애가 생기면 Node 24 고정 여부를 먼저 검토한다.
- 로그인과 저장소가 없어 사용자의 답변이나 연구 이력이 축적되지 않는다.

### 아직 구현하지 않은 기능

- 개인 연구.
- 봉사인도.
- 연설.
- 주제 연구와 성구 및 주제 노트 승격 체계.
- 통독과 개인별 진도 관리.
- 로그인, 사용자 계정, 데이터베이스.
- 실제 서버 단계 기반 진행률.

추가 기능은 기존 브라우저가 JSON API만 호출하는 경계를 유지한다. WOL 접근, 성경 코어 접근, AI 키와 답변 생성은 계속 서버에 둔다.

## 8. 검증된 기준선

- 성경 코어는 66권, 1,189장, 31,194절이다.
- 상호 참조는 65,578건이다.
- 현재 전체 테스트는 170개이며 168개 통과, 데이터 원본이 필요한 2개는 스킵된다.
- 1440px 데스크톱과 390px 모바일에서 답변 및 진행률 화면의 가로 넘침은 0건이었다.
- 실제 생활과 봉사 검증에서 15개 질문 모두 AI 답변이 생성됐고 링크 없는 문항은 0개였다.
- 해당 검증의 공식 출판물 링크는 총 16개이며 정확한 참고 항 범위 링크 5개와 질문 원문 링크 11개였다.
- 프로덕션 별칭의 홈과 진행률 모듈은 최종 확인에서 HTTP 200이었다.
- 프로덕션 `/api/options`는 최종 확인에서 21주를 반환했다.

이 기준선보다 수치가 줄어들면 단순한 콘텐츠 변화인지 파서 회귀인지 먼저 확인한다.
